# Плагины (WASM)

Плагин — WebAssembly-компонент мира `app` из [plugin-api/wit/app.wit](../../crates/plugin-api/wit/app.wit)
плюс [манифест](../api/apps.md). Сервер запускает его в песочнице
([wasm-host](../../crates/wasm-host/src/lib.rs), wasmtime). Планы и решения —
[ROADMAP.md](../../ROADMAP.md#плагины).

> Готово: HTTP-запросы, журнал, AppData, страница в панели, файлы пользователя по доступу,
> запрос доступа к папке, вход клиентов по паролям приложений, адреса `/.well-known/`,
> общие папки AppData между пользователями, настройки сервера, HTTP-запросы к другим серверам,
> хранилище плагина со скачиванием моделей, фоновые задачи.
> Дальше: «Открыть с помощью…» и доступ к открытому файлу.

Версия API — `0.2.16` ([plugin-api/src/lib.rs](../../crates/plugin-api/src/lib.rs)). До 1.0 минорная
версия может ломать: в 0.2.0 у записей AppData появились `etag` и `updated-at`, `write` возвращает запись.
Патч-версии только добавляют: 0.2.1 — импорт `shares`, 0.2.2 — `settings`, 0.2.3 — `http`, 0.2.4 — `storage`, 0.2.5 — `jobs` и мир `app-with-jobs`, 0.2.6 — `on` и `mime` у `[[jobs]]`, 0.2.7 — `use-ffmpeg`, 0.2.8 — события `file.deleted` и `file.moved`, 0.2.9 — `[limits]` в манифесте и импорт `limits`, 0.2.10 — `read-range`, `links` и ответ файлом (`x-rustcloud-send`), 0.2.11 — `links.video-stream`, 0.2.12 — `links.upload`, 0.2.13 — `use-onnx`, 0.2.14 — `[[open_with]]` в манифесте, полный экран и `close` на странице, `write-if-match`, `write-request-body` и `large_bodies`, блокировки, версии, `links.replace`, `tokens`, адреса из настроек и `permissions.frame`, 0.2.15 — `[[proxy]]` в манифесте и импорт `proxy`, 0.2.16 — `[[new_files]]` и `status` в манифесте; плагины, собранные под
0.2.0, работают без пересборки.

| `import proxy.self-url` | как сервис плагина достаёт до сервера — см. [Сервис через адрес облака](#сервис-через-адрес-облака) (с 0.2.15) |
| `import limits.get-limits` | что можно этому вызову: память, данные за раз, время — см. [Лимиты](#лимиты) (с 0.2.9) |

`user` — вошедший пользователь (`id`, `username`, `display-name`) или `none`.

## AppData

Своя папка плагина в файлах каждого пользователя: `.appdata/<id>/` ([files/src/appdata.rs](../../crates/files/src/appdata.rs)).

- Пути — относительные, через `/`: `templates/daily.md`. `..`, `.` и пустые имена — `invalid-path`.
- `write` создаёт папки по пути, заменяет файл и возвращает его запись. `read` — файл целиком, не больше
  [предела данных](#лимиты) (`too-large`); `read-range(path, offset, length)` — кусок (с 0.2.10).
- Запись (`entry`) — `name`, `is-dir`, `size`, `etag` (меняется вместе с содержимым, у папок пустой)
  и `updated-at` (RFC 3339). По etag удобно пересчитывать индексы и отвечать на `If-Match`.
- Всё — от имени пользователя запроса; без пользователя — `no-user`. Другого плагина и других
  пользователей плагин не видит.
- Это обычная скрытая папка пользователя: занимает его квоту (`no-space`), видна при «Показывать скрытые
  файлы», остаётся после удаления плагина. Записи плагина в AppData не попадают в журнал.

## Файлы пользователя

Плагин работает с файлами пользователя только в пределах [доступа](../api/grants.md), который дал
пользователь ([files/src/app_files.rs](../../crates/files/src/app_files.rs)).

- `granted()` — выданные файлы и папки; от них — `children`, `get`, `read` (не больше [предела данных](#лимиты)),
  `read-range(id, offset, length)` — кусок файла любого размера (с 0.2.10). Показать или отдать файл
  целиком — [без чтения в плагин](#большие-файлы).
- Всё за пределами доступа — `not-found`, будто его нет: плагин не узнаёт о других файлах.
- `write`, `create-file`, `create-folder`, `delete` — только при доступе на запись, иначе `read-only`.
  Саму выданную папку плагин удалить не может. `delete` кладёт в [корзину](../api/files.md#корзина)
  пользователя — тот может вернуть; плагин корзину не видит.
- Изменения попадают в [журнал](../admin.md#журнал) с полем `app` — видно, что сделал плагин.
  Чтения — одной строкой на запрос или порцию задач: «прочитал 50 файлов, 120 МБ» (индексация
  библиотеки не забивает журнал).
- Права манифеста (`permissions.files`, `files_write`) — потолок: больше пользователь выдать не сможет.
- `write-if-match(id, data, etag)` (с 0.2.14) — записать, только если файл не изменился с тех пор, как
  его прочитали: иначе `conflict`. Так два редактора не затирают правки друг друга. Проверка и запись —
  одно действие: запись, которую обогнали, не пройдёт.
- `write-request-body(id, if-match)` (с 0.2.14) — записать в файл тело запроса, потоком и любого
  размера: [тело запроса — в файл](#тело-запроса--в-файл).
- `lock(id, lock-id, seconds)`, `unlock(id, lock-id)`, `get-lock(id)` (с 0.2.14) —
  [блокировка](../api/files.md#блокировки): пока она держится (до часа, продлевается тем же `lock`),
  менять и удалять файл может только этот плагин, остальные получают `conflict`. Чужая блокировка —
  ошибка `locked` с её данными, так плагин отвечает по WOPI «файл заблокирован другим».
- `versions(id)`, `read-version(id, version-id, offset, length)` (с 0.2.14) — прежние
  [версии](../api/files.md#версии) файла; запись плагином сама сохраняет версию, как любая замена.

Доступ к папке страница плагина просит у пользователя:

```js
const folder = await rustcloud.requestAccess({ folder: 'Notes', write: true });  // { id, name }
```

Панель показывает диалог от имени облака ([AccessDialog.svelte](../../web/src/components/AccessDialog.svelte)):
создать папку `Notes` (или взять существующую с этим именем) либо выбрать другую, и что плагин сможет
с ней делать. Отказ — `requestAccess` отклоняется. Сам плагин выдать себе доступ не может.

## Общие папки

Пользователь может поделиться папкой своей AppData с другими пользователями — только для просмотра
или с правкой ([API](../api/app-shares.md), [files/src/app_shares.rs](../../crates/files/src/app_shares.rs)).
Так календарь делится календарями.

Делится владелец из панели — страница плагина только открывает диалог:

```js
await rustcloud.share({ path: 'calendars/work', label: 'Работа' });  // когда диалог закрыли
```

`path` — папка в AppData этого плагина, `label` — как её знает пользователь. Кому дать и с какими
правами, выбирают в диалоге панели ([AppShareDialog.svelte](../../web/src/components/AppShareDialog.svelte)).

У получателя тот же плагин видит папку через импорт `shares`:

- `received()` — что дали этому пользователю в этом плагине: `id`, `owner`, `path` у владельца,
  `label`, `write`;
- `read`, `write`, `list`, `delete` — как у AppData, с `share-id` и путём внутри общей папки
  (`list(id, "")` — сама папка; удалить саму папку нельзя);
- запись без права правки, и с паролем приложения только на чтение — `read-only`;
- закрытый доступ — `not-found`; `leave(id)` — получатель убирает папку у себя, у владельца она остаётся.

Запись идёт в квоту владельца. Плагин сам решает, как показать чужие папки: календарь кладёт их
в общий список с именем владельца, а свои индексы для них держит в AppData получателя.

## Настройки сервера

То, что нужно плагину для всего сервера — ключ API, модель, адрес сервиса, — он объявляет в манифесте
(`[[server_settings]]`, [формат](../api/apps.md#настройки-сервера)), администратор заполняет на вкладке
«Плагины». Плагин читает их на каждом запросе:

```rust
let values: serde_json::Value = serde_json::from_str(&settings::values()).unwrap_or_default();
let key = values["api_key"].as_str();      // None — не заполнено
```

`values()` — JSON-объект: `true`, число, строка или список строк; незаполненных ключей нет. Секреты
плагин получает, браузер — никогда. Отдавать их на свою страницу плагин не должен.
Воспользоваться ключом — через [сеть](#сеть).

## Сеть

Плагин ходит только на серверы, которые перечислил в манифесте, и только после того, как
администратор его включил (так он утверждает этот список):

```toml
[permissions]
network = [
  "api.openai.com",              # HTTPS, порт 443
  "*.huggingface.co",            # поддомены (не сам huggingface.co)
  "api.example.com:8443",        # другой порт
  "http://192.168.1.10:11434",   # обычный HTTP — только если указан явно
]
```

Путей в правиле нет — плагину доступен весь сервер. До 20 адресов. Обновление, которое добавляет
адрес, отключает плагин до подтверждения администратором.

Имя хоста из манифеста ведёт только в интернет: DNS имени в руках его владельца, и оно могло бы
указать на сам сервер или локальную сеть (базу данных, сервис метаданных облака, роутер). Поэтому
адреса `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10`, `::1`, `fc00::/7`,
`fe80::/10` и подобные для такого имени отбрасываются — в момент соединения, так что подменить ответ
DNS между проверкой и запросом нельзя (`failed(… no address in the internet …)`). В локальную сеть
плагин ходит, если в манифесте указан IP-адрес (`http://192.168.1.10:11434`) или адрес берётся из
настройки, которую заполняет администратор (`"{office_url}"`, ниже). Системный прокси (`HTTP_PROXY`)
не используется.

Адрес, который у каждого сервера свой (свой Collabora, свой Ollama), берётся из
[настройки сервера](#настройки-сервера) плагина (с 0.2.14): `"{office_url}"` — сервер из URL в текстовой
настройке `office_url`, которую заполняет администратор. Пока она пустая, адреса нет; администратор
меняет её — меняется и разрешённый адрес.

```toml
[permissions]
network = ["{office_url}"]
frame = ["{office_url}"]       # см. «Сервис поверх страницы»

[[server_settings]]
key = "office_url"
kind = "text"
label = { en = "Collabora Online address", ru = "Адрес Collabora Online" }
```

```rust
use rustcloud::app::http;

let answer = http::fetch(&http::Request {
    method: "POST".into(),
    url: "https://api.openai.com/v1/responses".into(),
    headers: vec![("authorization".into(), format!("Bearer {key}")),
                  ("content-type".into(), "application/json".into())],
    body: serde_json::to_vec(&question)?,
})?;   // answer.status, answer.headers, answer.body
```

- Запрос выполняет сервер ([wasm-host/src/http.rs](../../crates/wasm-host/src/http.rs)). Редиректы
  он проходит сам (до 5), если каждый ведёт на разрешённый адрес; иначе — `not-allowed`.
  `Authorization` и `Cookie` на другой хост не переносятся.
- Ответ — не больше [предела данных](#лимиты) (`too-large`). Большие файлы (модели) скачивает сервер — см.
  [Хранилище плагина](#хранилище-плагина).
- Ожидание ответа не входит в лимит работы плагина, но входит в [общее время](#лимиты) вызова (при ×1 — 60 с):
  после него — `timeout`.
- Заголовок `host` задавать нельзя (`invalid-request`), он берётся из URL.
- Ошибки: `not-allowed`, `invalid-request`, `too-large`, `timeout`, `failed(причина)` — нет
  соединения, DNS, TLS. HTTPS проверяется по общедоступным корневым сертификатам и сертификатам
  системы ([свой ЦС](../admin.md#плагины)).
- В лог сервера (уровень `debug`) — метод, хост, статус и время каждого запроса; попытка обратиться
  к чужому адресу — `warn`. Остальная часть URL в лог не попадает: в ней бывают ключи.

## Хранилище плагина

Одно на плагин для всего сервера, не для пользователя: модели, справочники, кэш
([plugin_storage.rs](../../crates/server/src/plugin_storage.rs)). Не входит в квоту пользователей,
работает и в запросах без пользователя. Размер пока не ограничен, но последний 1 ГБ диска оно не
занимает (`STORAGE_FULL`); администратор видит, что там лежит, и может очистить ([Плагины](../admin.md#плагины)).

**Только общее.** Всё, что связано с людьми (лица, теги, индексы их файлов), — в AppData
пользователя: хранилище видят все пользователи плагина, и через него данные одного попали бы
к другому. Сервер этого проверить не может — это правило для автора плагина.

```rust
use rustcloud::app::storage;

let model = storage::stat("models/faces.onnx")?;          // нет — not-found: ещё скачивается
let mut bytes = Vec::with_capacity(model.size as usize);
while (bytes.len() as u64) < model.size {
    bytes.extend(storage::read("models/faces.onnx", bytes.len() as u64, 16 << 20)?);
}
storage::write("cache/vocabulary.json", &data)?;
```

- Пути — имена через `/`, без пустых, `.` и `..` (`invalid-path`). `list(dir)` — файлы в папке
  и глубже, `""` — все; `delete` удаляет файл или папку со всем содержимым.
- `read(path, offset, length)` — не больше [предела данных](#лимиты) за раз, в конце файла меньше,
  за концом — пусто. Модель больше памяти плагина не поместится: попросите больше в `[limits]`.
- У файла — `size`, `sha256`, `updated-at`.
- Большие файлы кладёт сервер: [`[[downloads]]`](../api/apps.md#загрузки) в манифесте — путь,
  URL с адреса из `permissions.network` и SHA-256. Скачивается в фоне, когда плагин включён;
  пока файла нет, `stat` отвечает `not-found` — покажите пользователю «модель загружается».
- При удалении плагина его хранилище удаляется; AppData пользователей остаётся.

## Фоновые задачи

Для работы, которая не укладывается в запрос: индексация, метаданные фото, поиск лиц
([plugin_jobs.rs](../../crates/server/src/plugin_jobs.rs)). Плагин ставит задачи — **одна задача на
один элемент** («прочитать EXIF файла `<id>`»), сервер выполняет их потом порциями.

```toml
[[jobs]]
kind = "exif"          # a-z0-9-_, уникальный
batch = 50             # задач за один вызов run-batch, 1–1000 (по умолчанию 10)
time = 4               # работа плагина на порцию: в 4 раза больше, чем у его запроса

[[jobs]]
kind = "faces"
batch = 5
time = 16
memory = 8             # память порции: в 8 раз больше, чем у запроса плагина
```

`memory` и `time` — множители к [лимитам](#лимиты) самого плагина: 1, 2, 4, 8, 16, 32 или 64
(по умолчанию 1); вместе не больше ×64. Старые `time_seconds` и `memory_mib` (до 0.2.9)
читаются как ближайший множитель вверх. Сколько порций идёт одновременно — `workers` из `[limits]`.

### Задачи по событиям

Чаще всего ставить задачи вручную не нужно: вид с `on` получает их сам — по одной на файл, ключ —
id файла, `data` — имя события.

```toml
[[jobs]]
kind = "exif"
batch = 50
on = ["file.granted", "file.created", "file.changed", "file.deleted", "file.moved"]
mime = ["image/*", "video/mp4"]     # необязательно: только такие файлы
```

| Событие        | Когда                                                                 |
|----------------|-----------------------------------------------------------------------|
| `file.granted` | пользователь дал плагину папку — на каждый файл, что в ней уже лежит   |
| `file.created` | в такой папке появился файл: загрузка, копирование, плагин, возврат из корзины |
| `file.changed` | у файла там сменилось содержимое                                      |
| `file.deleted` | файл там удалён (в корзину) — сам или с папкой; задача — на каждый файл папки |
| `file.moved`   | файл переименован или перемещён — внутрь, наружу или внутри такой папки |

- Только папки, данные «навсегда» (`files = "folder"` или `"all"` в манифесте); открытый файл событий
  не даёт. Скрытые папки (AppData) не входят.
- Изменения, которые сделал сам плагин, его задач не ставят — без зацикливания.
- `file.deleted` приходит, когда файла уже нет: `files::get` ответит `not-found` — уберите его из
  своего индекса по id. После `file.moved` наружу файл тоже недоступен плагину.
- Задача одна на файл и вид: если файл успел смениться и удалиться, пока задача ждала, в `data`
  будет последнее событие.
- `mime` — `тип/подтип` или `тип/*`; без `mime` — любые файлы.

Плагин собирается под мир `app-with-jobs` (это `app` и экспорт `run-batch`); плагин без `[[jobs]]`
может оставаться на `app`. Плагин с `[[jobs]]`, но без экспорта, не загружается.

```rust
wit_bindgen::generate!({ path: "wit", world: "app-with-jobs" });
use rustcloud::app::jobs::{self, NewJob};

// В обработчике запроса — например, когда пользователь дал доступ к папке:
jobs::add(&photos.iter().map(|p| NewJob { kind: "exif".into(), key: p.id.clone(), data: String::new() })
    .collect::<Vec<_>>())?;

impl Guest for App {
    fn run_batch(user: User, jobs: Vec<Job>) -> Vec<Outcome> {
        jobs.iter().map(|job| match read_exif(&job.key) {
            Ok(()) => Outcome::Done,
            Err(Broken(why)) => Outcome::Failed(why),   // не получится: остаётся в ошибках
            Err(Busy(why)) => Outcome::Retry(why),      // позже: ещё раз, всего 5 попыток
        }).collect()
    }
    // fn handle(…) — как обычно
}
```

- **От имени пользователя.** Задачи ставятся для пользователя запроса (без пользователя — `no-user`)
  и выполняются от его имени: файлы — в пределах выданного им доступа, AppData — его. Пользователь
  забрал у плагина весь доступ — его задачи удаляются; заблокирован — ждут.
- **Ключ** — что обрабатывать, до 512 байт; задача с тем же видом и ключом заменяет прежнюю (файл
  изменился — поставьте ещё раз). `data` — что угодно до 4 КБ, вернётся в `job.data`. До 1000 задач
  за вызов `add` и до 200 000 задач плагина на пользователя (`TOO_MANY_JOBS`). `job.attempts` — сколько раз задачу уже пробовали.
- **Порция** — задачи одного вида и одного пользователя, не больше `batch`; на каждую — свой
  `outcome`, по порядку (не хватает — повтор). Модель, которую плагин грузит в начале порции,
  делится на все её задачи: для тяжёлых видов порция поменьше, но не 1.
- **Порция упала целиком** (паника, лимит памяти или времени) — её задачи дальше идут по одной:
  битый файл не мешает остальным. Повторы — через 30 с, 1, 2, 4 мин; после 5 попыток — ошибка.
  Выполненные задачи удаляются, с ошибкой — остаются, пока их не поставят снова.
- **Очередь по кругу:** плагин → пользователь → вид задачи. 50 000 фото одного пользователя и
  медленная нейросеть не задерживают остальных. Одновременно идёт
  [`[plugins] workers`](../configuration.md#plugins) порций; плагин в порции раз в 100 мс уступает
  поток, чтобы ответы на запросы не тормозили.
- **Прогресс:** `jobs::progress()` — по видам «осталось» и «ошибок» для пользователя, чтобы показать
  на своей странице. Администратор видит то же по всем пользователям и меняет размер порции и лимиты
  каждого вида на вкладке «Плагины».
- **Журнал сервера:** на каждую порцию строка — плагин, вид, пользователь, размер, сколько выполнено,
  с ошибкой, отложено и сколько задач плагина осталось:

  ```text
  INFO plugin jobs: photos/faces ×5 for alice: 4 done, 1 failed, 0 later; 4795 left
  ```

  Если «left» со временем не убывает — повод смотреть подробнее.

## Страница в панели

Пункт `ui.entry = "/app/<id>"` в [манифесте](../api/apps.md) открывает `#/app/<id>/…`: панель показывает
`/app/<id>/…` в `<iframe sandbox="allow-scripts allow-forms allow-downloads">` — у страницы свой
уникальный origin, она не видит cookie и данных облака ([AppFrame.svelte](../../web/src/components/AppFrame.svelte)).

Запросы к своим маршрутам страница делает через панель — [app-sdk.js](../../web/public/app-sdk.js):

```html
<script src="/app-sdk.js"></script>
<script>
  const { locale, theme, user } = await rustcloud.context;
  const reply = await rustcloud.fetch('/notes', { method: 'POST', body: JSON.stringify(note),
                                                  headers: { 'content-type': 'application/json' } });
</script>
```

- Панель выполняет запрос от имени пользователя, только к `/app/<id>/…` ([bridge.ts](../../web/src/lib/bridge.ts));
  `/../../api/…` и другие плагины — ошибка.
- Заголовки запроса: `content-type`, `accept`, `range`, `if-match`, `if-none-match`; страница получает
  обратно `content-type`, `content-disposition`, `content-range`, `etag`, `last-modified`.
- Тело запроса — текст (JSON) или байты: `ArrayBuffer`, типизированный массив, `Blob`, `File`, не больше
  [предела данных](#лимиты) плагина (`context.limits.body`, при ×1 — 16 МБ).
  Байты передаются без копирования и base64 (transferable `ArrayBuffer`). Ответ приходит байтами,
  поэтому работают `res.text()`, `res.json()` и `res.blob()`:

  ```js
  const thumb = await rustcloud.fetch(`/thumb/${id}`);
  img.src = URL.createObjectURL(await thumb.blob());
  await rustcloud.fetch('/upload', { method: 'PUT', body: file,
                                     headers: { 'content-type': file.type } });
  ```
- `context.theme` — `light` или `dark`, `locale` — `en` или `ru`, `limits.body` — сколько байт можно
  отправить за раз, `origin` — адрес панели (`https://cloud.example.com`; у самой страницы origin
  непрозрачный): его ждут внешние сервисы, например WOPI `PostMessageOrigin`.

### Полный экран

`rustcloud.setLayout('full')` показывает страницу на всё окно браузера, `'panel'` возвращает в область
страницы панели (с 0.2.14). Поверх страницы на весь экран панель всегда держит свою кнопку «×» в
правом верхнем углу: страница не может запереть пользователя. `rustcloud.close()` — то же, что эта
кнопка: открытый файл закрывается (назад к списку файлов или в папку файла), страница без файла
выходит из полного экрана. «Назад» в браузере закрывает страницу как обычно.

### Сервис поверх страницы

Редактор вроде Collabora Online в песочнице страницы плагина не работает: у вложенного iframe нет
своего origin, а значит, cookies и localStorage. Поэтому его показывает сама панель — поверх
страницы плагина, вне её песочницы (с 0.2.14):

```js
await rustcloud.openFrame({ url: editorUrl, fields: { access_token: token, access_token_ttl: '0' } });
rustcloud.onFrameMessage((data) => { /* PostMessage API редактора */ });
rustcloud.postToFrame({ MessageId: 'Host_PostmessageReady' });
rustcloud.closeFrame();
```

- Показать можно только адрес из `permissions.frame` (как в `network`, обычно `"{office_url}"`):
  администратор утверждает его, включая плагин и заполняя настройку. Другой адрес — ошибка.
- `fields` панель отправляет формой `POST` прямо в iframe — так WOPI-клиенты принимают токен
  ([Токены](#токены-для-других-серверов)); `method: 'get'` — открыть без формы.
- Страница плагина остаётся под сервисом и разговаривает с ним через панель: сообщения сервиса
  приходят в `onFrameMessage`, `postToFrame` отправляет только на его origin.
- Страница уходит на весь экран, кнопка «×» панели закрывает документ.
- Адреса из `frame` попадают в CSP панели (`frame-src`, `form-action`); других внешних адресов у
  панели нет.

### Сервис через адрес облака

С `frame` у сервиса свой адрес: администратор открывает его наружу, ставит TLS и прописывает в
сервисе адрес облака. С `[[proxy]]` (с 0.2.15) браузер ходит к сервису только через адрес облака,
WebSocket тоже, а администратор пишет один адрес — внутренний, как его видит сервер облака:

```toml
[[proxy]]
target = "{office_url}"                      # адрес или текстовая настройка сервера с ним
paths = ["/browser", "/cool"]                # пути в корне адреса облака
```

- Запрос к `/cool/…` облако передаёт на `http://collabora:9980/cool/…` как есть: метод, путь и query
  без декодирования, тела потоком. Сервис видит `Host` облака (из него он строит адреса своей
  страницы) и `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host`.
- **Пути** — 1–8 на прокси, до 4 прокси: `/` и до четырёх имён из строчных букв, цифр, `-`, `_`;
  не `/api`, `/app`, `/assets`, `/health`, без точек (файлы панели). Пути разных плагинов не
  пересекаются: второй такой плагин не запустится.
- **Кто достаёт до сервиса:** только браузер с сессией облака (cookie, не токен) пользователя,
  у которого сейчас открыт файл в этом плагине (доступ `session`, [Открыть с помощью](#открыть-с-помощью)).
  Без сессии — `401`, без открытого файла — `403 NO_OPEN_FILE`. WebSocket закрывается, когда файл
  закрыли (проверка раз в 30 с) или 5 минут нет трафика.
- **Откуда:** WebSocket и запросы, которые что-то меняют, — только со страниц самого облака (`Origin`
  совпадает с адресом, на который пришёл запрос), иначе `403 ORIGIN_NOT_ALLOWED`. Это вместо проверки
  `X-Requested-With`, которую страницы сервиса не делают.
- **Учётные данные облака сервис не получает:** cookie сессии облака и `Authorization` вырезаются,
  его собственные cookie проходят. Ставить cookie сессии облака или cookie с `Domain` сервис не может;
  редирект на свой адрес превращается в адрес облака. Заголовки ответа сервиса (CSP, кэш) остаются его,
  кроме тех, что действовали бы на всё облако: `Clear-Site-Data`, `Strict-Transport-Security`, CORS
  (`Access-Control-*`), `Service-Worker-Allowed`, `Refresh` отбрасываются, а service worker сервис
  поставить не может (`403 NO_SERVICE_WORKER`). Без `X-Frame-Options` облако ставит `SAMEORIGIN` —
  панель показывает сервис во фрейме.
- **Только свои пути:** путь с сегментом `.` или `..`, в том числе закодированным (`%2e%2e`), или с
  `\` — `400 BAD_PATH`: адрес сервиса иначе вывел бы запрос за пределы `paths`.
- **Лимиты** — `[plugins]`: соединений WebSocket на сервер и на пользователя, остальных запросов на
  пользователя одновременно (лишние — `429`), размер тела (`413`). Подключение к сервису — до 5 с,
  начало ответа — до 60 с (`502 SERVICE_UNREACHABLE`, `504 SERVICE_TIMEOUT`), весь ответ — до 10 минут.
  Query в лог не пишется: в нём токены сервиса.
- Показывает сервис панель, как с `frame`: `rustcloud.openFrame({ url })`, где `url` — адрес облака
  (`context.origin`) с путём из `paths`. Origin сервиса — origin облака.
- **Сервис доверенный.** Он работает на адресе облака, поэтому его скрипты могут действовать от имени
  пользователя, у которого открыт документ, пока он открыт. Администратор видит это, утверждая
  плагин; изменённый `[[proxy]]` при обновлении отключает плагин до нового подтверждения.

Сервис сам зовёт плагин обратно (WOPI) — по адресу, который даёт импорт `proxy.self-url()`:
адрес облака на соединении сервера с сервисом и порт, на котором слушает сервер, например
`http://172.19.0.3:8080` в сети Docker или `http://127.0.0.1:8080` на одном хосте. Плагин строит
из него `WOPISrc`. Этот адрес облако принимает и при `only_listed_urls` — но только с IP сервиса и
только на маршруты этого плагина `/app/<id>/…`. `none` — прокси нет, сервис не отвечает (тогда
остаётся адрес, найденный раньше) или сервер слушает другой адрес, чем тот, с которого уходит
соединение (`listen = "127.0.0.1:8080"`, а сервис в другой сети) — тогда плагину нужна своя настройка
адреса.

## Открыть с помощью

Плагин объявляет, какие файлы открывает (с 0.2.14), — в списке файлов появляется пункт
«Открыть в …», а файл без своего предпросмотра открывается в первом таком плагине по двойному
щелчку:

```toml
[[open_with]]
mime = ["application/vnd.oasis.opendocument.text", "text/*"]
page = "/edit"        # панель откроет #/app/<id>/edit?file=<id>
write = true          # менять файл (нужен permissions.files_write)
layout = "full"       # на всё окно (по умолчанию) или "panel"
label = { en = "Edit", ru = "Редактировать" }   # без него — «Открыть в <плагин>»
```

- Нужен `permissions.files` не ниже `opened`.
- Выбор пользователя в меню — согласие: панель выдаёт плагину [доступ](../api/grants.md) `session`
  к этому одному файлу, подтверждает его каждые 30 секунд и отзывает, когда страницу закрыли.
- По прямой ссылке (`#/app/<id>/edit?file=<id>`, перезагрузка страницы) панель сначала спрашивает
  пользователя; «больше не спрашивать для этого приложения» запоминается в браузере.
- Страница получает `?file=<id>` в адресе и `context.file = { id, name, mime_type, write }`; сам файл
  плагин читает и пишет через импорт `files`, как любой выданный.
- Ссылка на документ открывает его только тому, у кого есть доступ к файлу: чужой — `FILE_NOT_FOUND`.

## Новые файлы

В списке файлов кнопка «Создать» — папка, текстовый файл, Markdown и то, что добавили плагины
(с 0.2.16):

```toml
[[new_files]]
extension = "docx"
label = { en = "Document", ru = "Документ" }   # пункт меню и имя файла: «Документ.docx»
template = "/templates/empty.docx"            # путь плагина с содержимым; без него — пустой файл
```

- Панель предлагает имя (`Документ.docx`, занято — `Документ (2).docx`), пользователь может его
  поменять. Шаблон панель берёт `GET /app/<id><template>` с сессией пользователя — как страницу
  плагина, — и создаёт файл в открытой папке от имени пользователя. Доступа к папке плагину не нужно.
- Созданный файл сразу открывается в плагине, если его [`[[open_with]]`](#открыть-с-помощью) берёт
  этот тип; иначе — в первом плагине, который его открывает; если таких нет — просто появляется в списке.
- Расширение — 1–16 строчных латинских букв и цифр, у плагина не больше 20 видов.

## Состояние для администратора

Что плагин хочет сказать администратору — «Collabora отвечает», «модель не скачана», — он отдаёт на
своём пути (с 0.2.16):

```toml
status = "/status"
```

Вкладка «Состояние» в окне плагина (Администрирование → Плагины → «Настроить») делает
`GET /app/<id>/status` с сессией администратора, когда её открывают и по «Обновить». Ответ —
JSON-список строк:

```json
[
  {"level": "ok", "text": {"en": "Collabora answers", "ru": "Collabora отвечает"}},
  {"level": "warning", "text": "wopi_base_url is empty: using the panel's address"}
]
```

- `level` — `ok`, `info`, `warning` или `error`; `text` — строка или тексты по языкам (`en` — запасной).
- Проверяйте на месте, что нужно (discovery, есть ли модель в хранилище), — отчёт всегда свежий.
- Путь доступен любому вошедшему, как остальные маршруты плагина: секретов в нём не отдавайте.
- Пункт в боковой панели (`[ui]`) плагину не обязателен: без `[ui]` его нет в меню, а страницы
  «Открыть с помощью» и отчёт о состоянии работают.

## Токены для других серверов

Редактор документов вроде Collabora Online обращается к маршрутам плагина сам (WOPI), без сессии
пользователя. Плагин выдаёт ему токен на один файл (с 0.2.14,
[app_tokens.rs](../../crates/server/src/app_tokens.rs)):

```rust
let token = tokens::issue(&file_id, true, 10 * 3600)?;   // { token, expires-at }
// Collabora получает token и зовёт /app/<id>/wopi/files/<file>?access_token=<token>
```

- Сервер принимает токен в `?access_token=…` или `Authorization: Bearer …` на любом маршруте плагина и
  вызывает плагин от имени пользователя, которому токен выдан: `files` видит только этот файл, менять
  его можно, только если токен на запись. `tokens::current()` — файл и права токена этого запроса
  (`none` — запрос самого пользователя).
- Токен выдаётся на файл, к которому у плагина есть [доступ](../api/grants.md), не дольше 12 часов, и
  работает, пока этот доступ действует: пользователь отозвал доступ — токен отвечает `401`. Каждый
  вызов продлевает `session` открытого файла, как страница. Закрытая страница оставляет минуту, чтобы
  редактор успел сохранить.
- Токен подписан ключом сервера (`<data_dir>/app-tokens.key`, создаётся при первом запуске) и
  переживает перезапуск. Токеном нельзя выдать другой токен.

## Большие файлы

Оригинал фото, видео, модель — файл не должен проходить через память плагина: сервер отдаёт его сам,
потоком, с `Range` (перемотка видео) и `ETag` (кэш браузера), любого размера
([app_links.rs](../../crates/server/src/app_links.rs)). Источники — те же, что у `use.ffmpeg`:
`file:<id>` (файл, выданный пользователем), `appdata:<path>` (AppData пользователя),
`storage:<path>` (хранилище плагина). Доступ проверяется, как при чтении самим плагином.

**Ответ файлом.** Плагин отвечает заголовком `x-rustcloud-send`, тело пустое:

```rust
Response { status: 200, headers: vec![("x-rustcloud-send".into(), format!("file:{id}"))], body: vec![] }
```

Сервер отдаёт файл вместо ответа, отвечая на `Range` и `If-None-Match` запроса; из заголовков плагина
берёт `Content-Disposition` и `Cache-Control`. На запрос с токеном другого сервера (`tokens`) так
отдаётся только файл этого токена. Такой ответ идёт и через мост `rustcloud.fetch`, но
мост читает ответ целиком — для больших файлов нужна ссылка.

**Ссылки для страницы.** `<img src>` и `<video src>` из песочницы страницы уходят без cookie, поэтому
плагин даёт странице ссылки, которые сами говорят, чьи они:

```rust
use rustcloud::app::links::{self, Target};
let urls = links::create(&[Target::File(id), Target::Appdata("thumbs/1.webp".into())]);
// ["/api/v1/app-links/…", …] — по одной на источник, Ok или Err(not-found)
```

- Ссылка живёт, пока жива сессия пользователя, но не больше 12–13 часов (до полного часа): выход, конец сессии, отзыв
  доступа, удаление или изменение файла её закрывают (`404`). Доступ проверяется на каждом запросе. Сервер подписывает
  ссылки ключом, который создаёт при старте: после перезапуска страница просит новые.
- У одного файла одной версии в одной сессии — одна и та же ссылка, поэтому браузер их кэширует.
  Выдавайте пачкой (до 1000 за вызов) — например, миниатюры всей страницы ленты сразу.
- Только для запросов из браузера с сессией: с паролем приложения и в фоновых задачах — `no-session`.
- Файлы, которые браузер не показывает сам (не картинки, видео, звук, текст), отдаются как
  загрузка (`attachment`) и в песочнице CSP — подписанная ссылка не исполнит HTML на домене облака.
- Выданная ссылка на файл пользователя попадает в журнал как его чтение плагином.
- Ответы ссылок идут с `Access-Control-Allow-Origin: *` (без cookie): страница может забрать файл и
  `fetch`-ем, например hls.js.

### Загрузка со страницы

`files.create-file` берёт содержимое целиком, не больше [предела данных](#лимиты), — видео так не
загрузить. Ссылка для загрузки отправляет файл со страницы прямо на сервер, потоком, мимо плагина:

```rust
let url = links::upload(&folder_id, "IMG_0042.mov", false)?; // "/api/v1/app-links/…"
```

```js
const response = await fetch(url, { method: 'POST', body: file }); // 201 и файл в JSON (`Node`)
```

- Папка — выданная пользователем с правом записи; иначе `not-found` (не видна плагину) или `other`
  (доступ только на чтение). Имя должно быть свободно, если не `overwrite = true`, — иначе `other`.
- Ссылка — на одну загрузку, которую нужно начать в течение 15 минут. Не удалась (обрыв, квота) —
  можно повторить по той же ссылке; удалась — ссылка закрыта (`404`). Как и ссылки на чтение, живёт,
  пока жива сессия, и только для запросов из браузера.
- Права проверяются и при выдаче, и при загрузке: отозванный доступ, выход или отключённый плагин
  её закрывают. Файл проходит квоту и [`files.max_upload_mib`](../configuration.md#files), как любая
  загрузка; размер больше ничем не ограничен.
- Загрузки в AppData и хранилище плагина по ссылке нет.
- Загрузка попадает в [журнал](../admin.md#журнал) с полем `app` и, в отличие от записей самого
  плагина, ставит его задачи `file.created` (`file.changed` при замене): файл прислал пользователь,
  миниатюру к нему можно сделать фоновой задачей.
- Загрузка одним запросом: оборвалась — начинается заново. Загрузка частями — в
  [ROADMAP](../../ROADMAP.md).
- `links.replace(file, if-match)` (с 0.2.14) — такая же ссылка, но новое содержимое выданного файла:
  прежнее становится [версией](../api/files.md#версии), ответ — `200` с файлом. С `if-match` загрузка
  отвечает `409 FILE_CHANGED`, если файл тем временем изменился.

### Тело запроса — в файл

Другой сервер присылает файл в теле запроса к плагину — так Collabora сохраняет документ (WOPI
`PutFile`). `files.write-request-body(id, if-match)` (с 0.2.14) кладёт тело запроса, на который
отвечает плагин, в выданный файл: сервер переносит его потоком, мимо памяти плагина
([app_bodies.rs](../../crates/server/src/app_bodies.rs)).

```rust
// POST /wopi/files/<id>/contents
let node = files::write_request_body(&id, None)?;   // или Some(&etag)
```

- Тело больше [предела данных](#лимиты) плагин обычно не получает: запрос отвергается
  (`413 FILE_TOO_LARGE`). Плагин с `large_bodies = true` в манифесте получает такой запрос без тела и с
  заголовком `x-rustcloud-body-size: <байт>`, а тело сервер держит на диске
  (`<data_dir>/tmp/request-bodies`) и удаляет, когда плагин ответил. Тело в пределах — плагин
  получает, как раньше, и может сохранить тем же вызовом.
- Тело держится на диске только для пользователя, который может менять файлы: запросу без входа или
  с доступом только на чтение большое тело — по-прежнему `413`. Предел — сколько пользователь может
  загрузить сейчас: `files.max_upload_mib`, остаток квоты и свободное место на диске (последний 1 ГБ
  не занимается); тело, которое замолчало на минуту, обрывается. Файл проходит квоту, прежнее содержимое становится [версией](../api/files.md#версии), блокировки и
  `if-match` действуют, как у `write-if-match`.
- Время переноса не входит во время плагина, как у инструментов `use.*`.
- Вне запроса (в фоновой задаче) — `other`.

### Видео

H.264 в MP4 браузер играет по обычной ссылке, с перемоткой. Для остального — HLS, который сервер
делает сам ([stream.rs](../../crates/media/src/stream.rs)), нужен `use.ffmpeg`:

```rust
use rustcloud::app::links::{self, StreamMode, Target};
let playlist = links::video_stream(&Target::File(id), StreamMode::Copy)?;  // "/api/v1/app-links/…/index.m3u8"
```

| Режим  | Что делает                                   | Когда                                                     |
|--------|----------------------------------------------|-----------------------------------------------------------|
| `copy` | перепаковывает во фрагменты MP4, без перекодирования | кодек браузер умеет, контейнер — нет: H.264 в MKV, AVI, TS; HEVC там, где браузер его декодирует |
| `h264` | перекодирует в H.264 до 720p (OpenH264), звук — AAC | кодек браузер не умеет: HEVC в Firefox, MPEG-2, VP9 в Safari |

- Кусок по 6 с делается, когда плеер его просит; в `copy` куски режутся по ключевым кадрам (их
  список сервер получает один раз). Плейлист и init-сегмент сервер помнит по версии файла.
- На странице — hls.js (`hls.loadSource(playlist)`), в Safari — прямо `<video src>`. hls.js кладите
  в архив плагина рядом со страницей, не берите с CDN: сервер может стоять без интернета. Что умеет
  браузер, страница узнаёт сама: `video.canPlayType('video/mp4; codecs="hvc1"')`,
  `MediaSource.isTypeSupported(…)`; кодек файла — из `use-ffmpeg.get-metadata`.
- Перекодирование тяжёлое: каждый кусок — процесс ffmpeg в песочнице с пределами `[media]`, процессы
  делятся со всеми плагинами, а для запросов из интерфейса один всегда в резерве.

## Песочница

- **Новый экземпляр на каждый запрос** — запросы не делят память, падение затрагивает только свой запрос.
- **Лимиты** — см. [ниже](#лимиты). Превышение памяти или времени, паника — `500 APP_FAILED` и
  запись в журнале.
- **WASI пустой:** нет файлов, сокетов, переменных окружения. Всё — только через импорты WIT
  (HTTP — через [`http`](#сеть)).
- **HTTP:** плагин не получает `Cookie` и `Authorization`, не может поставить cookie; его ответы идут
  с CSP `sandbox` — страница плагина никогда не работает от имени облака — и встраиваются только
  в страницы облака (`frame-ancestors 'self'`). Тело запроса — не больше предела данных (`413`),
  а без входа — не больше 256 КБ.
- **Заголовки ответа** доходят до браузера только те, что касаются страницы плагина: `Content-Type`,
  `Content-Length`, `Content-Disposition`, `Content-Range`, `Cache-Control`, `ETag`, `Last-Modified`,
  `Location`, `Vary`, DAV-заголовки (`DAV`, `Allow`, `Lock-Token`, `Schedule-Tag`…) и свои `X-…`.
  `Set-Cookie`, CSP, `Clear-Site-Data`, `Strict-Transport-Security`, CORS, `Service-Worker-Allowed`,
  `Refresh`, `Link` отбрасываются: они действовали бы на всё облако. Service worker плагин
  установить не может (`403 NO_SERVICE_WORKER`).
- **Пароль приложения** (Basic) работает для изменений только из программ (CalDAV-клиенты): запрос
  со страницы браузера (`Origin`, `Sec-Fetch-Site`) — `403 CSRF_CHECK_FAILED`.
- **Одновременно** работает до 4 экземпляров на ядро; лишние запросы ждут до 5 с, потом
  `429 SERVER_BUSY`. Плагин, занятый вычислением, каждые 100 мс уступает поток другим запросам.
- Проверки CSRF и сессии — те же, что у API ([CSRF](../api/README.md#csrf)).
- **Окна браузера** `alert()`, `confirm()`, `prompt()` в песочнице не работают (`confirm` сразу
  возвращает `false`) — спрашивайте пользователя своим `<dialog>`, как заметки и календарь.

## Лимиты

Что можно плагину, задают три числа — множители к базе ([plugin-api/src/limits.rs](../../crates/plugin-api/src/limits.rs)).
Плагин объявляет их в манифесте, администратор может поставить другие в «Расширенных настройках»
([Плагины](../admin.md#плагины)). Всё остальное считается из них, поэтому нельзя выставить такие
значения, при которых плагин падает при любом поведении:

```toml
[limits]
memory = 4    # 1, 2, 4, 8, 16, 32 или 64 (по умолчанию 1)
time = 2      # то же
workers = 2   # порций фоновых задач одновременно, 1–16 (по умолчанию 1)
```

| При ×1                                                     | Растёт с  | При `memory = 4, time = 2` |
|------------------------------------------------------------|-----------|----------------------------|
| 64 МБ памяти                                               | `memory`  | 256 МБ                     |
| 16 МБ данных за один вызов: файл целиком, ответ `http`, миниатюра, тело запроса, чтение хранилища | `memory` | 64 МБ |
| 10 с работы самого плагина                                 | `time`    | 20 с                       |
| 60 с на весь вызов, с ожиданием сервера                    | `time`    | 120 с                      |

- Данные — всегда четверть памяти: они проходят через память плагина в нескольких копиях.
  Больше — `too-large`, а не падение.
- Ожидание ответов сервера (AppData, файлы) не входит в работу плагина: занятая база не роняет
  плагин. Время инструментов `use.*` (ffmpeg) не входит и в общее время: у них свои пределы.
- `memory` не больше `[plugins] max_memory` сервера ([настройки](../configuration.md#plugins)),
  и у фоновых задач тоже, даже если вид задачи просит больше.
- Обновление, которое просит больше прежнего, отключает плагин до подтверждения — как новые права.
  «Больше» — это и новые или более тяжёлые `[[jobs]]`, `large_bodies`, другие `[[downloads]]` и
  `[[server_settings]]`.
- Свои пределы плагин узнаёт сам:

  ```rust
  let limits = rustcloud::app::limits::get_limits();
  // limits.memory_bytes, limits.data_bytes, limits.time_ms, limits.wall_ms
  ```

## Свой плагин на Rust

```toml
# Cargo.toml
[lib]
crate-type = ["cdylib"]

[dependencies]
wit-bindgen = "0.63"
```

```rust
// src/lib.rs
wit_bindgen::generate!({ path: "wit", world: "app" });   // копия plugin-api/wit

struct Hello;

impl Guest for Hello {
    fn handle(user: Option<User>, _request: Request) -> Response {
        let name = user.map_or("guest".to_owned(), |u| u.username);
        Response {
            status: 200,
            headers: vec![("content-type".into(), "text/plain; charset=utf-8".into())],
            body: format!("Hello, {name}!").into_bytes(),
        }
    }
}

export!(Hello);
```

```sh
rustup target add wasm32-wasip2
cargo build --release --target wasm32-wasip2
```

Полный пример с проверками песочницы — [wasm-host/tests/apps/echo](../../crates/wasm-host/tests/apps/echo/src/lib.rs).
Отдельный плагин в своём репозитории, со сборкой в Actions и `use.ffmpeg`, —
[examples/plugin-template](../../examples/plugin-template): серверу от него нужен только `app.wit`.

## Лицензия плагина

Контракт (`crates/plugin-api`, `wit/app.wit`), [шаблон](../../examples/plugin-template) и примеры
кода на этой странице — под MIT или Apache-2.0, на выбор. Сам сервер — под AGPL-3.0-or-later, но
плагин общается с ним только через контракт и работает отдельным WebAssembly-компонентом, поэтому
лицензию плагина выбирает его автор, в том числе закрытую и платную.

## Установка

```text
<data_dir>/apps/hello/        # папка = id из манифеста
  manifest.toml
  app.wasm                    # target/wasm32-wasip2/release/hello.wasm
```

Встроенные плагины ([apps/](../../apps)) собираются в Docker-образе и лежат в `builtin_apps_dir`
(`/usr/share/rustcloud/apps`); они читаются первыми. Плагины админа — в `<data_dir>/apps`.

Плагины читаются при запуске сервера. Неверный манифест, занятый id, несовместимая версия API или
неподходящий компонент — плагин пропускается с предупреждением в журнале, сервер работает дальше.
После этого плагин отвечает на `/app/hello/…` и появляется в [`GET /api/v1/apps`](../api/apps.md).

Из интернета плагины ставятся через [каталог](plugin-catalog.md).
