# Каталог плагинов

Каталог — список плагинов, которые администратор ставит из интернета: Администрирование → Плагины →
Каталог. Это один файл `index.json` в репозитории
[RustCloud/_plugins](https://github.com/RustCloud/_plugins); сервер читает его по адресу
`https://raw.githubusercontent.com/RustCloud/_plugins/main/index.json`.

> Готово: формат и его проверка ([plugin-api/src/catalog.rs](../../crates/plugin-api/src/catalog.rs),
> `scripts/check.py` в репозитории каталога). Дальше: вкладка «Каталог» на сервере, потом подпись
> файла ([ROADMAP.md](../../ROADMAP.md#плагины)).

## Формат

```json
{
  "schema": 1,
  "plugins": [
    {
      "id": "rc-office",
      "name": { "en": "Office", "ru": "Офис" },
      "description": {
        "en": "Edit documents, spreadsheets and presentations in Collabora Online.",
        "ru": "Документы, таблицы и презентации в Collabora Online."
      },
      "author": "RustCloud",
      "license": "MIT OR Apache-2.0",
      "source": "https://github.com/RustCloud/rc-office",
      "versions": [
        {
          "version": "0.2.3",
          "api": "^0.2.16",
          "url": "https://github.com/RustCloud/rc-office/releases/download/v0.2.3/rc-office.zip",
          "sha256": "52e450c6d31027d5298b4f0ba65083621eb8c7156ef985def82a18fcc8d61bd0",
          "size": 113899,
          "notes": { "en": "New documents from the Files page.", "ru": "Новые документы из «Файлов»." }
        }
      ]
    }
  ]
}
```

| Поле | Что это |
|---|---|
| `schema` | версия формата, сейчас `1`. Сервер не читает каталог другой версии |
| `id` | `id` из манифеста плагина; в каталоге один раз |
| `name`, `description` | по коду языка, `en` обязателен; описание — одна-две фразы, до 500 символов |
| `author`, `license` | автор и лицензия (SPDX, например `MIT OR Apache-2.0`) |
| `source` | исходный код, адрес `https://` |
| `homepage` | необязательно: страница плагина, если это не `source` |
| `versions` | опубликованные версии в любом порядке, каждая один раз |
| `version`, `api` | `version` и `api` из манифеста в архиве |
| `url` | архив: адрес `https://` или путь относительно `index.json` (для зеркала) |
| `sha256`, `size` | SHA-256 архива (64 строчные hex-цифры) и размер в байтах, до 64 МБ |
| `notes` | необязательно: что изменилось, по коду языка |

Архив — тот же zip, что ставится вручную: `manifest.toml` и `app.wasm` в корне или в одной папке
([Установка](plugins.md#установка)).

## Правила

- **Версия не меняется после публикации.** `url` — файл релиза по тегу, не `latest`; у опубликованной
  версии нельзя поменять `url`, `sha256`, `size` и `api`. Исправление — новая версия. Удалить версию
  можно.
- **Права плагина — только из манифеста в архиве.** Каталог говорит, откуда взять плагин, а что ему можно,
  администратор видит и утверждает при включении, как при ручной установке.
- **Неизвестные поля сервер пропускает**, поэтому новые необязательные поля добавляются без смены
  `schema`. Проверка в репозитории каталога их не пропускает: там это опечатка.
- **Сломанная запись не прячет остальные:** сервер пропускает её и пишет причину.

## Что делает сервер

1. Скачивает `index.json`, когда администратор открывает каталог; хранит копию в памяти. О сервере в
   запросе ничего, кроме `User-Agent: RustCloud/<версия>`.
2. Для каждого плагина показывает **новейшую версию, чей `api` подходит к API сервера**; предварительные
   версии (`0.4.0-beta.1`) — только если других нет. Если подходящей нет — «нужна более новая версия
   сервера». Если плагин стоит и в каталоге версия новее — «есть обновление».
3. При установке скачивает архив (не больше `size`), сверяет размер и SHA-256, затем `id`, `version`
   и `api` манифеста с записью — и ставит как обычный архив: новый плагин выключен, обновление остаётся
   включённым, только если не просит больше прав.

Типы и эти проверки — [`rustcloud_plugin_api::catalog`](../../crates/plugin-api/src/catalog.rs).

## Публикация версии

`index.json` собирается сам, руками его не правят. В репозитории каталога лежит `sources.json` — список
репозиториев плагинов с описанием, автором и лицензией (название, `id` и `api` берутся из манифеста):

```json
{
  "keep": 3,
  "plugins": [
    {
      "repo": "RustCloud/rc-office",
      "description": { "en": "…", "ru": "…" },
      "author": "RustCloud",
      "license": "MIT OR Apache-2.0"
    }
  ]
}
```

Необязательно: `homepage`, `asset` (имя архива, если в релизе несколько `.zip`), `keep` для одного
плагина, `prereleases: true`.

1. Автор выпускает релиз с архивом плагина: workflow [шаблона](../../examples/plugin-template) собирает zip.
2. Workflow **Update** в репозитории каталога (пока вручную, потом по расписанию) читает релизы каждого
   репозитория, берёт `keep` новейших с архивом, скачивает и проверяет новые (размер, SHA-256, манифест)
   и коммитит `index.json`. Релиз без архива или со сломанным пропускается с предупреждением. Если у уже
   опубликованной версии поменялся архив — ошибка, `index.json` не меняется.
3. Workflow **Check** проверяет `index.json` на каждый push и pull request.
