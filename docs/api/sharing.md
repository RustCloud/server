# Общий доступ к файлам

Владелец открывает файл или папку другим пользователям или группе — только для чтения или с
правом изменять. Код — [files/src/sharing.rs](../../crates/files/src/sharing.rs), группы —
[auth/src/groups.rs](../../crates/auth/src/groups.rs). В интерфейсе — «Доступ…» в меню файла,
вкладка «Доступные мне», группы — «Администрирование → Группы».

## Что можно получателю

Доступ открывает узел и всё, что в нём. Получатель находит его в `GET /api/v1/files/shared` и
работает по id обычными запросами [файлов](files.md):

| | чтение | с правом изменять |
|---|---|---|
| `GET /files/{id}`, `…/children`, `…/content`, `…/zip`, `…/thumbnail` | да | да |
| загрузка, новые папки, замена содержимого | `403 READ_ONLY_SHARE` | да |
| переименование и перенос внутри общей папки | `403 READ_ONLY_SHARE` | да |
| удаление (в корзину владельца) | `403 READ_ONLY_SHARE` | да |
| копирование к себе | да | да |

- Саму общую папку переименовывает, переносит и удаляет только владелец (`403 SHARED_ROOT`).
- Папки владельца выше общей не видны: `path` в `GET /files/{id}` начинается с общей папки.
- Перенести своё в чужую папку нельзя (`400 CROSS_OWNER_MOVE`) — только скопировать.
- Всё записанное идёт в квоту владельца; «кто изменил» — получатель.
- Версии, корзина, публичные ссылки, доступ приложений и «Доступ…» остаются за владельцем
  (`404` для получателя).
- Что лежит в корзине, получателю не видно. Пока владелец отключён, его общие папки не видны никому.

## Владелец

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /api/v1/files/{id}/access` | — | `[Access]` — кому открыт узел |
| `POST /api/v1/files/{id}/access` | `{username, write?}` или `{group_id, write?}` | `201 Access` |
| `PATCH /api/v1/access/{id}` | `{write}` | `Access` |
| `DELETE /api/v1/access/{id}` | — | `204` — закрыть доступ |

```json
{"id": "…", "node_id": "…", "user": {"id": "…", "username": "bob", "display_name": "bob"},
 "group": null, "write": false, "created_at": "…"}
```

- Тому же человеку или группе ещё раз — меняет `write`, новой записи не создаёт.
- Делиться можно с группами, в которых состоишь сам (`404 GROUP_NOT_FOUND` иначе).
- Нельзя: корень (`400 ROOT_FOLDER`), корзину и то, что в ней (`400 IN_TRASH`), `.appdata`
  (`400 CANNOT_SHARE` — данными приложений делятся [из приложений](app-shares.md)), себе
  (`400 SHARE_WITH_SELF`).
- **Имена не перебрать.** Имя, которого нет, принимается и показывается так же, но ничего не
  открывает; появившийся позже пользователь с этим именем его не получает. Поэтому люди в списке —
  по имени пользователя (`display_name` = `username`).

## Получатель

`GET /api/v1/files/shared` → `[Received]`, по имени:

```json
{"id": "…", "node": {…}, "owner": {"id": "…", "username": "alice", "display_name": "Alice"},
 "write": true, "group": null}
```

- Открыто и лично, и через группу — одна запись с наибольшими правами.
- `DELETE /api/v1/access/{id}` — убрать у себя то, что открыто лично (открытое группе убирает
  владелец или администратор, исключив из группы).

## Группы

Создаёт и наполняет администратор:

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /api/v1/admin/groups` | — | `[{id, name, members: [{id, username, display_name}]}]` |
| `POST /api/v1/admin/groups` | `{name}` | `201` группа |
| `PATCH /api/v1/admin/groups/{id}` | `{name}` | `204` |
| `DELETE /api/v1/admin/groups/{id}` | — | `204`; открытое группе закрывается |
| `PUT /api/v1/admin/groups/{id}/members/{user_id}` | — | `204` |
| `DELETE /api/v1/admin/groups/{id}/members/{user_id}` | — | `204` |
| `GET /api/v1/groups` | — | `[{id, name}]` — группы, в которых состоит пользователь |

Имя — 1–64 символа, уникальное (`409 GROUP_EXISTS`).

## Пока не сделано

- Лента изменений и WebDAV показывают только свои файлы, без открытых другими.
- Загрузка по частям в чужую папку резервирует место в квоте загружающего, а файл ложится в квоту
  владельца.
