# Приложения

Приложения (плагины) сервера — для навигации клиентов. Код —
[server/src/apps.rs](../../crates/server/src/apps.rs), манифест —
[plugin-api](../../crates/plugin-api/src/manifest.rs).

## Список

`GET /api/v1/apps` — нужна [авторизация](README.md#аутентификация).

```json
{
  "api_version": "0.2.10",
  "apps": [{
    "id": "files",
    "version": "0.1.0-alpha.1",
    "api": "=0.2.10",
    "name": {"en": "Files", "ru": "Файлы"},
    "provides": {"rustcloud:files": "0.1.0"},
    "ui": {"icon": "folder", "entry": "/files", "routes": ["links", "search", "trash"]}
  }],
  "limits": {"files": {"data_bytes": 16777216}}
}
```

| Поле           | Что это                                                                 |
|----------------|-------------------------------------------------------------------------|
| `api_version`  | версия API плагинов этого сервера                                       |
| `id`           | уникальный, `a-z0-9-`; не меняется                                      |
| `api`          | с какими версиями API плагинов работает приложение (semver-условие)     |
| `name`         | название по коду языка; `en` есть всегда и используется по умолчанию    |
| `provides`     | интерфейсы для других приложений и их версии                            |
| `permissions`  | потолок прав: `files` (`none`, `opened`, `folder`, `all`), `files_write` — см. [доступ](grants.md); `network` — серверы для HTTP-запросов плагина, см. [Сеть](../dev/plugins.md#сеть); `frame` — сервисы, которые панель показывает поверх страницы, см. [Сервис поверх страницы](../dev/plugins.md#сервис-поверх-страницы); `use` — возможности сервера (`ffmpeg`), см. [use.*](../dev/use.md); `images = "any"` (с 0.2.18) — странице можно показывать картинки с любых сайтов, см. [Страница плагина](../dev/plugins.md#что-может-страница) |
| `ui`           | пункт в боковой панели; нет — у приложения нет страниц                  |
| `ui.icon`      | имя иконки; незнакомое клиент заменяет общей                            |
| `ui.entry`     | куда ведёт пункт                                                        |
| `ui.routes`    | первые сегменты пути, на которых пункт подсвечен (кроме сегмента `entry`) |
| `well_known`   | адреса обнаружения протоколов: `caldav = "/dav/"` — см. [ниже](#адреса-обнаружения) |
| `server_settings` | настройки плагина для всего сервера — см. [ниже](#настройки-сервера) |
| `downloads`    | файлы, которые сервер скачивает в хранилище плагина — см. [ниже](#загрузки) |
| `jobs`         | виды фоновых задач с размером порции, множителями памяти и времени и событиями файлов, которые их ставят — см. [плагины](../dev/plugins.md#фоновые-задачи) |
| `proxy`        | пути облака, которые уходят к сервису рядом с ним: `target`, `paths` — см. [Сервис через адрес облака](../dev/plugins.md#сервис-через-адрес-облака) |
| `new_files`    | новые файлы в меню «Создать»: `extension`, `label`, `template` — см. [Новые файлы](../dev/plugins.md#новые-файлы) |
| `status`       | путь, с которого вкладка «Состояние» читает отчёт плагина — см. [Состояние](../dev/plugins.md#состояние-для-администратора) |
| `open_with`    | какие файлы приложение открывает: `mime`, `page`, `write`, `layout`, `label` — см. [Открыть с помощью](../dev/plugins.md#открыть-с-помощью) |
| `limits` (в манифесте) | что приложению нужно от сервера: множители `memory`, `time`, `workers` — см. [Лимиты](../dev/plugins.md#лимиты); нет поля — ×1 |
| `limits` (рядом с `apps`) | по id: `data_bytes` — сколько байт за раз принимает приложение; столько пропускает мост страницы |
| `frames` (рядом с `apps`) | по id: origins сервисов, которые панель может показать для страницы приложения (`permissions.frame` с адресами из настроек) |
| `proxies` (рядом с `apps`) | по id: пути облака, которые уходят к сервису приложения (`[[proxy]]` с заданным адресом); их панель тоже может показать для страницы |

Порядок в списке — порядок в панели: сначала встроенные, затем WASM-плагины, которые поставляются
с сервером, и установленные в `<data_dir>/apps/` — по имени папки. Отключённых плагинов
([Администрирование → Плагины](../admin.md#плагины)) в списке нет.

## Маршруты плагинов

`<любой метод> /app/<id>/<путь>?<query>` — запрос передаётся WASM-плагину `<id>` как есть, кроме
заголовков `Cookie` и `Authorization`. Плагин получает пользователя по сессии или по
[паролю приложения](app-passwords.md) (`Authorization: Basic`) с правом на этот плагин. Запрос
с другого сайта (`Sec-Fetch-Site: cross-site` или `same-site` — ссылка, форма, картинка там)
сессию не передаёт: плагин видит гостя, даже если браузер прислал cookie. Ответ плагина отдаётся с CSP `sandbox`, который пускает страницу только на сам сервер
(кроме `permissions.frame` и `permissions.images`, см. [Что может страница](../dev/plugins.md#что-может-страница)), `Set-Cookie`
отбрасывается. Ответ с заголовком `x-rustcloud-send: file:<id> | appdata:<path> | storage:<path>` — сервер отдаёт
этот файл вместо тела (с `Range`, `ETag`), если пользователь запроса может прочитать его через
плагин; иначе `404 FILE_NOT_FOUND` ([Большие файлы](../dev/plugins.md#большие-файлы)).
Ошибки: `404 APP_NOT_FOUND`, `500 APP_FAILED`, `413` — тело больше предела данных плагина
(при ×1 — 16 МБ, см. [Лимиты](../dev/plugins.md#лимиты)).
Подробнее — [Плагины](../dev/plugins.md).

## Адреса обнаружения

`<любой метод> /.well-known/<имя>` → `301` на `/app/<id><путь>` плагина, который попросил это имя
в `well_known` манифеста. Так CalDAV-клиенты находят [календарь](../apps/calendar.md)
(`/.well-known/caldav` → `/app/calendar/dav/`). Одно имя — у одного плагина: второй плагин с тем же
именем не загружается, в логе — «app "x" asks for /.well-known/caldav, which app "calendar" already has».
Имя, которое никто не просил, — `404`.

## Настройки сервера

Плагин может объявить настройки для всего сервера: ключ API, имя модели, адрес сервиса. Администратор
заполняет их на вкладке «Плагины», плагин читает через импорт `settings` ([плагины](../dev/plugins.md#настройки-сервера)).

```toml
[[server_settings]]
key = "api_key"                    # a-z0-9_, уникальный
kind = "secret"                    # bool | number | text | list | secret
label = { en = "API key", ru = "Ключ API" }   # en обязателен
hint = { en = "From your account page" }      # необязательно

[[server_settings]]
key = "timeout"
kind = "number"
unit = "s"                         # подпись у числа
label.en = "Timeout"
```

- Порядок полей в форме — порядок в манифесте; не больше 50 настроек.
- `secret` после сохранения в браузер не возвращается: в ответе API — только `secrets_set`.
- Значения проверяются по `kind`: `text` и `secret` — до 10 000 символов, `list` — до 1000 строк.

## Загрузки

Большие файлы — модель, справочник — в архив плагина не кладут: их скачивает сервер в
[хранилище плагина](../dev/plugins.md#хранилище-плагина), как только администратор включил плагин.

```toml
[permissions]
network = ["*.huggingface.co"]

[[downloads]]
path = "models/faces.onnx"                     # путь в хранилище
url = "https://cdn.huggingface.co/…/faces.onnx"  # только с адресов из permissions.network
sha256 = "…"                                   # обязательно: не совпала — файл не сохраняется
size = 174000000                               # необязательно: для прогресса
```

- Скачиваются только файлы, которых нет или у которых другая сумма: обновление плагина с новой
  `sha256` скачивает файл заново, остальные остаются.
- Ход загрузки и ошибка — на вкладке «Плагины» ([API](admin.md#плагины)); после ошибки — «Повторить».
- До 20 файлов; размер не ограничен.

Приложение с неверным манифестом, повторным `id` или несовместимой версией API сервер не загружает —
на вкладке «Плагины» оно показано с причиной.

См. также: [ROADMAP — плагины](../../ROADMAP.md#плагины)

## Ссылки страниц плагинов

`GET /api/v1/app-links/<token>` — без cookie и токена: ссылку выдаёт плагин своей странице
(импорт `links`, [Большие файлы](../dev/plugins.md#большие-файлы)). Отдаёт файл, как
[скачивание](files.md): `Range`, `If-None-Match`, `ETag`, `Cache-Control: private, no-cache`, CSP
`sandbox`. `404 LINK_NOT_FOUND` — подпись неверна, сессия закончилась, плагин отключён, доступ отозван
или файл изменился. Ответы — с `Access-Control-Allow-Origin: *`.

Поток видео (`links.video-stream`): `GET /api/v1/app-links/<token>/index.m3u8` — плейлист HLS,
`…/init.mp4` и `…/<n>.m4s` — init-сегмент и куски fMP4, которые сервер делает при запросе
(`Cache-Control: private, max-age=86400`: ссылка называет одну версию файла). Плагину нужен
утверждённый `use.ffmpeg`, иначе — `404`.

Загрузка (`links.upload`, [Загрузка со страницы](../dev/plugins.md#загрузка-со-страницы)):
`POST /api/v1/app-links/<token>`, тело — сырые байты файла → `201 Node`. Ссылка — на одну удачную
загрузку, начать — в течение 15 минут; `404 LINK_NOT_FOUND` — подпись неверна, срок вышел, ссылка
использована, сессия закончилась или плагин отключён. Ошибки загрузки — как у
[обычной](files.md#загрузка): `409 NAME_TAKEN`, `413 FILE_TOO_LARGE`, `413 QUOTA_EXCEEDED`, а без
доступа к папке — `404 FILE_NOT_FOUND` или `403 READ_ONLY`.

CORS для `/api/v1/app-links/…` открыт любому origin (страницы плагинов — в песочнице со своим
origin): ссылки не принимают cookie, их права — в подписи.
