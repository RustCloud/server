# Общий доступ к данным приложений

Пользователь делится папкой данных приложения (AppData) с другим пользователем: например, календарём —
только для просмотра или с правкой. Правила — [files/src/app_shares.rs](../../crates/files/src/app_shares.rs),
маршруты — [server/src/app_shares.rs](../../crates/server/src/app_shares.rs).

- **Делится только владелец**, и только из панели: страница плагина открывает диалог
  `rustcloud.share(…)` ([плагины](../dev/plugins.md#общие-папки)), но выдать доступ сама не может.
  Администратор чужими данными не делится.
- **Плагин работает с общей папкой от имени получателя** через импорт `shares` — только в этом
  приложении и в пределах выданных прав. Запись идёт в квоту владельца.
- **Доступ заканчивается**, когда владелец его закрывает, получатель убирает папку у себя,
  папку удаляют или удаляют один из аккаунтов. Пока владелец отключён, его данные не видны никому.
- В интерфейсе — «Настройки → Общий доступ к данным приложений»: чем вы поделились и что дали вам,
  с кнопками «Отозвать» и «Убрать». Выдача и отзыв попадают в [журнал](../admin.md#журнал).

## Объект `AppShare`

```json
{
  "id": "…", "app_id": "calendar", "path": "calendars/work", "label": "Работа",
  "owner": { "id": "…", "username": "alice", "display_name": "Alice" },
  "user":  { "id": "…", "username": "bob",   "display_name": "Bob" },
  "write": false, "created_at": "…"
}
```

| Поле    | Что это                                                                   |
|---------|---------------------------------------------------------------------------|
| `path`  | папка в AppData владельца для этого приложения                            |
| `label` | как приложение назвало папку при выдаче (название календаря)              |
| `owner` | чьи данные                                                                |
| `user`  | кому открыты                                                              |
| `write` | `true` — можно менять, `false` — только смотреть                          |

## Запросы

| Запрос                            | Тело                                              | Ответ          |
|-----------------------------------|---------------------------------------------------|----------------|
| `GET /api/v1/app-shares`          | —                                                 | `{given: [AppShare], received: [AppShare]}`, новые первыми |
| `POST /api/v1/app-shares`         | `{app_id, path, label?, username, write?}`        | `201 AppShare` |
| `DELETE /api/v1/app-shares/{id}`  | —                                                 | `204`          |

- `POST` той же папки тому же пользователю ещё раз меняет `write` и `label`, новой записи не создаёт.
- `label` — до 100 символов; пустой — имя папки.
- `DELETE` может сделать и владелец («отозвать»), и получатель («убрать у себя»).

- **Имена не перебрать.** Выдача пользователю, которого нет, отвечает так же (`201`), хранится
  и показывается в `given` так же, но никому ничего не открывает (таблица `app_shares_unmatched`);
  зарегистрированный позже пользователь с этим именем её тоже не получает. Поэтому в `given`
  получатель показан по имени пользователя (`display_name` = `username`), а не по отображаемому
  имени. Выдача отключённому пользователю — обычная: заработает, когда его включат.

Ошибки: `404 APP_NOT_FOUND`, `404 FILE_NOT_FOUND` (нет такой папки в AppData), `400 INVALID_NAME`
(пустой или недопустимый путь), `400 SHARE_WITH_SELF` (это вы сами), `404 SHARE_NOT_FOUND`.
