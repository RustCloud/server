# Файлы

Модуль [files](../../crates/files/src/lib.rs), маршруты — [http.rs](../../crates/files/src/http.rs),
логика — [service.rs](../../crates/files/src/service.rs). Все запросы требуют
[авторизации](README.md#аутентификация).

## Объект `Node`

```json
{
  "id": "…", "parent_id": "…", "name": "report.pdf", "is_dir": false,
  "size": 52133, "mime_type": "application/pdf", "etag": "<sha256>",
  "created_at": "…", "updated_at": "…", "modified_at": "…"
}
```

`parent_id: null` — корневая папка. `etag` меняется вместе с содержимым, у папок — `null`.
`updated_at` — когда сервер последний раз менял элемент (содержимое, имя, место). `modified_at` —
время изменения содержимого, которое передал клиент при загрузке (mtime файла на устройстве); если
не передал — время загрузки. Переименование, перемещение и копирование его не меняют, восстановленная
[версия](#версии) возвращается со своим. Сервер этим временем ни для чего не пользуется: сроки корзины и
версий считает по своим часам.
У того, что лежит в [корзине](#корзина), есть ещё `trashed_at` — когда удалено. В списке папки и
`GET /files/{id}` у файла, который держит приложение, есть `lock` — см. [Блокировки](#блокировки).

## Чтение

| Запрос                                 | Ответ                                    |
|----------------------------------------|------------------------------------------|
| `GET /api/v1/files/root`               | корневая папка `Node`                    |
| `GET /api/v1/files/{id}`               | `{node, path}` — `path`: папки выше, для «хлебных крошек» |
| `GET /api/v1/files/{id}/children`      | `[Node]` — содержимое папки              |
| `GET /api/v1/files/search?q=отчёт`     | `[Node]` — имя содержит `q`, без учёта регистра; корзина не входит |
| `GET /api/v1/usage`                    | `{used_bytes, versions_bytes, quota_bytes}` — `used_bytes` вместе с корзиной и [версиями](#версии) |

## Скачивание

`GET /api/v1/files/{id}/content`

- `Range: bytes=…` → `206` (докачка, перемотка видео); вне файла → `416`.
- `If-None-Match` со значением заголовка `ETag` из прошлого ответа → `304`.
- `?download=1` — «Сохранить как» вместо показа в браузере.
- HTML, SVG и подобное отдаются так, что не исполняются на домене облака
  ([content.rs](../../crates/files/src/content.rs)); JavaScript — как `text/plain`, чтобы страница
  облака не могла подключить его через `<script src>`.
- PDF браузер показывает без песочницы, поэтому PDF, записанный не самим пользователем (открытый
  ему другим, загруженный другим в его общую папку или посетителем публичной ссылки), только
  скачивается.

### Папка архивом

`GET /api/v1/files/{id}/zip` — папка со всем содержимым одним zip-архивом
([archive.rs](../../crates/files/src/archive.rs)).

- Архив пишется по ходу отправки: сервер не держит его ни в памяти, ни на диске, поэтому
  `Content-Length` нет, а докачка (`Range`) не работает.
- Файлы лежат без сжатия (фото и видео уже сжаты); файлы от 4 ГиБ — в ZIP64. Пустые папки
  тоже попадают в архив, время изменения — [mtime](#объект-node) файла.
- Архив корневой папки называется `files.zip`, корзины в нём нет. Папку в корзине не скачать
  (`400 IN_TRASH`), файл — `400 NOT_A_FOLDER`, больше 100 000 файлов и папок — `400 TOO_MANY_FILES`.
- Если файл не прочитался посреди архива, ответ просто обрывается: клиент получает битый архив.
- Каждый архив занимает поток сервера, пока его читают, поэтому одновременно пишется не больше 16
  архивов на весь сервер (дальше — `429 SERVER_BUSY`), а клиент, который минуту ничего не читает,
  получает оборванный архив.
- В журнале — `file.download` с числом файлов и размером.

### Превью

`GET /api/v1/files/{id}/thumbnail[?size=small|large]` — превью фото или видео в WebP
([thumbnails.rs](../../crates/server/src/thumbnails.rs)); по публичной ссылке —
`GET /api/v1/public/{token}/thumbnail?node=<id>[&size=…]`.

- `small` (по умолчанию) — квадрат 256×256 для списков, `large` — до 1280 по длинной стороне.
- Делает медиа-движок (ffmpeg в песочнице): все форматы фото, что он читает (JPEG, PNG, WebP,
  HEIC, AVIF, RAW-снимки), и кадр видео. Без движка (`media_tools_dir` не задан) —
  `404 NO_THUMBNAIL`; есть ли превью на сервере, видно по `thumbnails` в `GET /api/v1/info`.
- Хранятся в `data_dir/thumbnails` по SHA-256 содержимого: одинаковые файлы делят превью,
  изменённый файл получает новое. Не запрошенные 30 дней удаляются. Файл, из которого превью не
  вышло, запоминается и больше не мучает движок (`404 NO_THUMBNAIL`).
- По публичной ссылке превью файлов, загруженных посетителями ссылки, не делаются
  (`404 NO_THUMBNAIL`): иначе любой мог бы скормить движку файл, сделанный для атаки на него.
  Владелец видит их превью у себя как обычно.
- `ETag` и `Cache-Control: private, max-age=86400`; интерфейс добавляет `&v=<etag файла>`, чтобы
  браузер не показывал старое превью.

## Загрузка

`POST /api/v1/files/{folder_id}/upload?name=<имя>[&overwrite=true][&mtime=<время>]` → `201 Node`

Тело — сырые байты файла, не `multipart`. Поток пишется сразу в хранилище, размер не
ограничен памятью.

```sh
curl -H "Authorization: Bearer $TOKEN" --data-binary @photo.jpg \
  "http://localhost:8080/api/v1/files/$FOLDER/upload?name=photo.jpg"
```

`PUT /api/v1/files/{id}/content` — заменить содержимое существующего файла → `Node`. Прежнее
содержимое становится [версией](#версии). С заголовком `If-Match: "<etag>"` замена удаётся, только если
файл не изменился, иначе `409 FILE_CHANGED`: проверка и замена — одно действие, две одновременные
замены с одним `If-Match` не пройдут обе. Принимает тот же `?mtime=`.

`mtime` — секунды Unix (`1730985600`, можно с дробной частью) или RFC 3339
(`2024-11-07T13:20:00Z`). Не раньше 1970 года и не больше чем на сутки вперёд, иначе
`400 INVALID_MTIME`; хранится с точностью до микросекунды.

Ошибки: `409 NAME_TAKEN` (без `overwrite`), `413 FILE_TOO_LARGE`
([`files.max_upload_mib`](../configuration.md#files)), `413 QUOTA_EXCEEDED`.

### Загрузка по частям

Для больших файлов и плохой связи: файл приходит кусками по порядку, оборванный кусок отправляется
заново с того места, где кончился предыдущий
([uploads.rs](../../crates/files/src/uploads.rs)).

| Запрос                                         | Ответ                                       |
|------------------------------------------------|---------------------------------------------|
| `POST /api/v1/files/{folder_id}/uploads`       | `201 Upload` — начать: `{name, size, overwrite?, mtime?}` |
| `PUT /api/v1/files/uploads/{id}?offset=<байт>` | `Upload` — следующий кусок, тело — сырые байты |
| `GET /api/v1/files/uploads/{id}`               | `Upload` — сколько принято (`received`)     |
| `GET /api/v1/files/uploads`                    | `[Upload]` — незаконченные загрузки пользователя |
| `POST /api/v1/files/uploads/{id}/finish`       | `201 Node` — собрать файл: `{sha256}`       |
| `DELETE /api/v1/files/uploads/{id}`            | `204` — отменить, принятое удаляется        |

`Upload`: `{id, folder_id, name, size, received, overwrite, mtime, created_at, expires_at}`.

- **Начало.** Имя, папка и место проверяются сразу: `409 NAME_TAKEN`, `413 FILE_TOO_LARGE`,
  `413 QUOTA_EXCEEDED`, `413 STORAGE_FULL`. Заявленный `size` сразу занимает квоту — другие загрузки
  его уже не получат. Одновременно не больше 20 загрузок у пользователя (`429 TOO_MANY_UPLOADS`).
- **Куски строго по порядку.** `offset` должен равняться `received`, иначе `409 WRONG_OFFSET` (в
  `message` — нужное смещение). Кусок, оборвавшийся на середине, не принимается целиком: после
  обрыва спросить `GET …/uploads/{id}` и продолжить с `received`. Куски дальше заявленного размера —
  `400 PART_TOO_LARGE`. Размер куска любой, но кусков не больше 10 000 (`409 TOO_MANY_PARTS`):
  удобно 8–64 МиБ.
- **Завершение.** Когда принято всё (`409 UPLOAD_INCOMPLETE`, если нет), `finish` с hex SHA-256
  всего файла. Файл появляется так же, как при обычной [загрузке](#загрузка): `overwrite`, версии,
  `mtime`, [лента изменений](#лента-изменений). Хэш не совпал — `400 CHECKSUM_MISMATCH`, загрузка
  удаляется, начинать заново. Имя заняли или папку удалили за это время — ошибка как при загрузке,
  а загрузка остаётся: можно освободить имя и завершить снова или отменить.
- **Брошенные.** Загрузка без нового куска 24 часа (`expires_at`) удаляется вместе с кусками;
  дальше — `404 UPLOAD_NOT_FOUND`.
- Пока идёт `finish`, куски и второй `finish` получают `409 UPLOAD_FINISHING`. Сборка читает куски
  из хранилища и пишет файл заново — на больших файлах это занимает время, а на диске ненадолго
  нужно место на файл дважды.

## Изменение

| Запрос                                 | Тело                       | Ответ      |
|----------------------------------------|----------------------------|------------|
| `POST /api/v1/files/{id}/folders`      | `{name}`                   | `201 Node` |
| `PATCH /api/v1/files/{id}`             | `{name?, parent_id?, modified_at?}` — переименовать, переместить, сменить mtime файла (RFC 3339) | `Node` |
| `POST /api/v1/files/{id}/copy`         | `{parent_id, name?}`       | `201 Node` |
| `DELETE /api/v1/files/{id}`            | —                          | `204` — в [корзину](#корзина); в корзине — навсегда, папки со всем содержимым |

Ошибки: `400 MOVE_INTO_ITSELF`, `400 COPY_INTO_ITSELF`, `400 ROOT_FOLDER`, `400 INVALID_NAME`,
`400 IN_TRASH`, `400 TRASH_FOLDER`.

## Корзина

Удалённое попадает в скрытую папку `.trash` в корне пользователя
([trash.rs](../../crates/files/src/trash.rs)); она создаётся при первом удалении.

| Запрос                                 | Ответ                                    |
|----------------------------------------|------------------------------------------|
| `GET /api/v1/files/trash`              | папка корзины `Node`; содержимое — `GET /files/{id}/children` |
| `POST /api/v1/files/{id}/restore`      | `Node` — вернуть в папку, откуда удалено |
| `DELETE /api/v1/files/{id}`            | `204` — для того, что в корзине: удалить навсегда |
| `DELETE /api/v1/files/trash`           | `204` — очистить корзину                 |

- Восстанавливается то, что удалили само, — элементы верхнего уровня корзины; папка — со всем
  содержимым. Если исходной папки нет или она тоже в корзине — в корень. Занятое имя получает
  номер: `report (2).pdf`.
- Пока элемент в корзине, его публичные ссылки отвечают `404 SHARE_NOT_FOUND`, а [доступ плагинов](grants.md) к нему
  приостановлен; после восстановления всё работает снова. Поиск корзину не показывает.
- В корзину ничего нельзя загрузить, создать, скопировать или переместить (`400 IN_TRASH`) — только
  удалить. Переместить из корзины можно: это то же восстановление. Саму `.trash` нельзя
  переименовать, переместить или удалить (`400 TRASH_FOLDER`).
- Корзина занимает квоту. Через [`files.trash_days`](../configuration.md#files) дней (по умолчанию 30)
  удалённое исчезает само.
- Удаление плагином тоже идёт в корзину.

Ошибки: `400 NOT_IN_TRASH` — восстановить можно только элемент верхнего уровня корзины.

## Блокировки

Редактор документов (через свой плагин) блокирует файл, пока его редактирует
([locks.rs](../../crates/files/src/locks.rs)): до конца блокировки менять и удалять файл может только
это приложение. Панель, API и другие плагины получают `409 FILE_LOCKED`; переименовать и переместить
можно. Блокировка заканчивается, когда приложение её снимает, когда её не продлили (не дольше часа
за раз) или когда владелец снял её сам.

```json
"lock": {"lock_id": "…", "app_id": "office", "user_id": "…", "expires_at": "…"}
```

| Запрос                            | Ответ                                         |
|-----------------------------------|-----------------------------------------------|
| `DELETE /api/v1/files/{id}/lock`  | `204` — снять блокировку (если редактор пропал) |

Плагины берут блокировки через импорт `files` — см. [плагины](../dev/plugins.md#файлы-пользователя).

## Версии

Замена файла — загрузкой с `overwrite`, `PUT …/content`, плагином — сохраняет прежнее содержимое
версией ([versions.rs](../../crates/files/src/versions.rs)).

| Запрос                                              | Ответ                                    |
|-----------------------------------------------------|------------------------------------------|
| `GET /api/v1/files/{id}/versions`                   | `{versions, keep, days}` — версии от новых к старым и сколько их хранится |
| `GET /api/v1/files/{id}/versions/{version}/content` | содержимое версии, как [скачивание](#скачивание) (`Range`, `ETag`, `?download=1`) |
| `POST /api/v1/files/{id}/versions/{version}/restore`| `Node` — сделать версию текущей          |

Версия: `{id, size, etag, modified_by, modified_at, created_at}` — `modified_at` — когда это
содержимое записали, `created_at` — когда его заменили.

- **Сколько хранится.** Версия остаётся, если она среди последних
  [`files.versions_keep`](../configuration.md#files) (по умолчанию 10) **или** моложе
  `files.versions_days` дней (по умолчанию 30, считая от замены). Удаляется только та, что не проходит
  ни по одному условию — сразу после новой версии и раз в час. Оба `0` — версии не хранятся.
- **Частые сохранения склеиваются.** Если файл снова сохраняет тот же человек меньше чем через
  5 минут после последней версии (или после создания файла), новой версии нет — иначе редактор с
  автосохранением заполнил бы список. Те же байты ещё раз — тоже не версия.
- **Восстановление** не теряет текущее: оно само становится версией, даже если его только что
  сохранили.
- **Квота.** Версии занимают квоту владельца, но уступают файлам: если для записи не хватает места,
  первыми удаляются самые старые версии. Файлы сами по-прежнему не могут превысить квоту.
- Версии уходят вместе с файлом, когда его удаляют навсегда; в корзине они остаются. Копия файла
  начинается без версий. [AppData](../dev/plugins.md#appdata) плагинов версий не хранит.

Ошибки: `404 VERSION_NOT_FOUND`, `400 NOT_A_FILE`, `400 IN_TRASH` — восстановить версию файла в
корзине нельзя.

## Лента изменений

Для клиентов синхронизации: что изменилось в файлах пользователя с прошлого раза, по порядку
([changes.rs](../../crates/files/src/changes.rs)).

| Запрос                                   | Ответ                                         |
|------------------------------------------|-----------------------------------------------|
| `GET /api/v1/files/changes`              | `{changes: [], cursor, more: false}` — курсор «сейчас», с него начинать |
| `GET /api/v1/files/changes?cursor=…`     | `{changes, cursor, more}` — изменения после курсора, до 1000 за раз |
| `GET /api/v1/files/changes/watch`        | `text/event-stream`: событие `changes`, когда в ленте появилось новое |

Запись ленты — `{id, kind}`: `id` файла или папки и что с ним случилось — `created`, `changed`
(содержимое или `mtime`), `moved` (перемещение или переименование), `deleted`. Имён в ленте нет:
каким узел стал, клиент узнаёт через `GET /api/v1/files/{id}`. Один `id` может встретиться
несколько раз — важно его нынешнее состояние; `404` в ответ — узел уже удалён.

- **Как пользоваться.** Взять курсор без параметра, затем обойти дерево (`children`) — всё, что
  изменится во время обхода, будет в ленте. Дальше спрашивать с последним `cursor`; при `more: true` —
  сразу ещё раз.
- **Папка — одна запись.** Перемещённая, скопированная, удалённая или восстановленная папка — одна
  запись о ней самой: появившуюся папку клиент обходит целиком, исчезнувшую убирает со всем
  содержимым.
- **Скрытые папки** (`.имя` — AppData, корзина и любые свои) и всё, что в них, в ленту не попадают.
  Удаление в корзину и перенос в скрытую папку — `deleted`, восстановление и перенос обратно —
  `created`. Файлы, чьё имя начинается с точки (`.gitignore`), в ленте есть.
- **Срок.** Записи хранятся 30 дней. Более старый курсор (или курсор не с этого сервера, например
  после восстановления базы из копии) — `410 CURSOR_EXPIRED`: клиент обходит всё заново и берёт новый
  курсор. Курсор — непрозрачная строка; чужая — `400 INVALID_CURSOR`.
- **Подсказки.** `…/changes/watch` — [server-sent events](https://html.spec.whatwg.org/multipage/server-sent-events.html):
  событие `changes` без данных, не чаще раза в секунду, и комментарии раз в 15 секунд, чтобы
  соединение не закрыли. После подключения и после каждого события клиент читает ленту. Соединение
  само закрывается через 10 минут — клиент открывает новое (с новым access-токеном). У пользователя
  не больше 10 таких соединений (`429 TOO_MANY_WATCHERS`). Подсказка — только повод спросить:
  клиент, который не держит соединение, просто спрашивает ленту раз в несколько минут.
- Запись делается сразу после изменения, не в одной транзакции с ним: если сервер упадёт ровно
  между ними, изменение в ленту не попадёт. Клиенту стоит изредка (раз в сутки) сверять дерево целиком.

## Доступ

Все проверки прав — в одной функции `Files::check_access`
([service.rs](../../crates/files/src/service.rs)). Чужой файл отвечает `404`, а не `403`,
чтобы не выдавать его существование.
