# Администрирование

Пункт «Администрирование» в боковой панели видят только администраторы. Первый
зарегистрированный аккаунт — администратор.

## Сервер

Первая вкладка — что с сервером: версия и коммит сборки, сколько работает, система и ядро, в
контейнере ли, ядра процессора и нагрузка, память машины (и лимит контейнера, если он задан),
память и потоки процесса RustCloud, база данных (PostgreSQL или SQLite, версия, размер), есть ли
`use.ffmpeg` и `use.onnx`. Ниже — карточка [«Хранилище»](#хранилище).

API: [`/api/v1/admin/system`](api/admin.md#сервер)

## Пользователи

Вкладка «Пользователи»: создать аккаунт, сделать администратором, отключить, задать квоту
и новый пароль. Отключённый аккаунт не может войти, его сессии перестают действовать.
Себя отключить или лишить прав нельзя (`CANNOT_CHANGE_SELF`).

API: [`/api/v1/admin/users`](api/auth.md#пользователи-админ)

## Настройки

Вкладки «Настройки» (`[server]`: адрес, сеть), «Аккаунты», «Файлы», «Плагины», «Журнал» — по одной на таблицу
[конфигурации](configuration.md). Применяются сразу и сохраняются в `rustcloud.toml`.
Параметры из переменных окружения показаны, но заблокированы.

API: [`/api/v1/admin/settings`](api/admin.md#настройки)

## Плагины

Вкладка «Плагины»: все плагины сервера, также те, что не загрузились, с причиной. В строке —
состояние, «Включить»/«Отключить», «Удалить»; кнопка **«Настроить»** открывает окно плагина с вкладками:

- **Настройки** — то, что плагин объявил сам (адрес Collabora, модель…), см. «Настройки» ниже;
- **Состояние** — работает ли, что плагин сообщает о себе (если объявил путь
  [`status`](dev/plugins.md#состояние-для-администратора): «Collabora отвечает», «нет модели»),
  хранилище и загрузки, фоновые задачи;
- **Системные** — что ему можно (доступ к файлам, сеть, сервисы, `use.*`) и ресурсы
  (бывшие «Расширенные настройки»).

| Откуда            | Что можно                                                       |
|-------------------|-----------------------------------------------------------------|
| часть сервера     | `files` — работает всегда                                       |
| поставляется с сервером | календарь, заметки (`builtin_apps_dir`): отключить, ресурсы |
| установлен        | из `<data_dir>/apps`: отключить, ресурсы, обновить, удалить     |

- **Отключённый плагин** пропадает из боковой панели, его маршруты отвечают `404 APP_NOT_FOUND`,
  адреса `/.well-known/` не работают. Данные пользователей (AppData), доступы и пароли приложений
  остаются — включите снова, и всё на месте. Применяется сразу, без перезапуска.
- **Включая плагин**, администратор утверждает, что он может просить у пользователей и куда
  ходить в сеть: строка под названием — доступ к файлам, адреса обнаружения и «Сеть» — серверы,
  к которым плагин может отправлять HTTP-запросы. Других адресов у плагина нет; отключённый
  плагин в сеть не ходит.
- **Не может работать**: неверный манифест или компонент, плагин для другой версии API, тот же id,
  что у другого, или адрес `/.well-known/`, который уже занял плагин выше по списку.
  Исправьте и перезапустите сервер или отключите мешающий плагин.
- **Установка** — кнопка «Установить плагин…»: архив `.zip` с `manifest.toml` и `app.wasm`
  (в корне или в одной папке, остальные файлы не нужны). Плагин проверяется и компилируется
  до того, как попадёт в `<data_dir>/apps/<id>`; неудачная установка ничего не меняет.
  **Новый плагин ставится отключённым** — посмотрите, что он может просить, и включите.
- **Обновление** — тот же архив с тем же `id`. Включённый плагин остаётся включённым, если новая
  версия просит не больше прежней (доступ к файлам, адреса `/.well-known/`, сеть, сервисы, ресурсы),
  иначе отключается до вашего подтверждения. Выбранные вами ресурсы сохраняются. Плагины, которые
  поставляются с сервером, архивом не заменить (`PLUGIN_EXISTS`).
- **Удаление** — только установленных; поставляемые с сервером отключают. Данные пользователей
  остаются: установите плагин снова — и они на месте. Хранилище плагина удаляется.
- **Возможности сервера (`use.*`)** — тяжёлый нативный код для плагинов: `use.ffmpeg` и
  `use.onnx` (нейросети; [как защищён сервер](dev/use.md#как-сервер-защищает-себя)). Строка прав
  плагина показывает «Возможности: use.ffmpeg, use.onnx»; включая плагин, вы их утверждаете. Над
  списком — есть ли ffmpeg на сервере, его версия, работают ли нейросети, какие модели сейчас в
  памяти и какие слои защиты действуют (rlimits, no_new_privs, seccomp, Landlock) — на вкладке «Сервер». Настройки —
  разделы «Медиа (use.ffmpeg)» (`[media]`) и «Нейросети (use.onnx)» (`[onnx]`) ниже.
- **Фоновые задачи** — если плагин их выполняет (индексация, обработка фото): по каждому виду —
  сколько задач осталось и сколько с ошибкой у всех пользователей и размер порции из манифеста.
  Сколько порций плагина идёт одновременно — на вкладке «Системные» плагина, всех плагинов вместе —
  «Фоновых задач одновременно» в разделе «Плагины» ниже (`[plugins] workers`). Над списком —
  сколько памяти фоновые задачи всех включённых плагинов займут одновременно в худшем случае.
  Каждая порция пишет строку в лог сервера: если число оставшихся задач не убывает, загляните в лог.
- **Хранилище плагина** — его общие файлы на сервере: модели, справочники, кэш. Строка «Хранилище:
  размер, файлов» — список файлов и «Очистить». Файлы, которые плагин просит в манифесте
  (`[[downloads]]`), сервер скачивает сам, когда плагин включён: под строкой — ход загрузки, после
  ошибки — причина и «Повторить». Скачивается только с адресов из «Сети» плагина, сумма SHA-256
  проверяется. Очистка удаляет всё, файлы из манифеста скачиваются заново. Хранилище лежит там же,
  где файлы пользователей, и в квоты не входит — следите за местом на диске.
- **Настройки** — если плагин их объявил ([`server_settings`](api/apps.md#настройки-сервера)):
  ключ API, модель и т. п. Секреты после сохранения не показываются: пустое поле оставляет сохранённый,
  «Очистить» — удаляет. Плагин получает значения со следующего запроса.
- **Сервис через адрес облака** (`[[proxy]]`, например офис с Collabora). Строка прав говорит
  «Показывает сервис http://collabora:9980 по путям /browser, /cool этого сервера». Браузер ходит к
  сервису через адрес облака, так что сервису не нужны ни свой порт наружу, ни TLS, ни адрес облака
  в его настройках. Цена — **доверие**: сервис работает на адресе облака, и его скрипты могут
  действовать от имени пользователя, который открыл в плагине документ, пока документ открыт.
  Включайте, только если доверяете сервису (свой контейнер Collabora — да). До сервиса достаёт только
  вошедший пользователь с открытым в плагине файлом и только по путям из манифеста; лимиты — в
  разделе «Плагины» ниже ([`[plugins]`](configuration.md#plugins)). Пример compose:

  ```yaml
  services:
    rustcloud:
      image: ghcr.io/rustcloud/server:latest
      ports: ["8080:8080"]
    collabora:
      image: collabora/code
      environment:
        extra_params: --o:ssl.enable=false --o:ssl.termination=true   # termination — если облако за HTTPS
      # ни ports, ни aliasgroup1: Collabora доверится облаку, которое придёт к ней первым
  ```

  В настройках плагина — `http://collabora:9980`. Сервис зовёт облако обратно по его внутреннему
  адресу в этой сети: облако принимает его только с адреса сервиса и только на маршруты плагина.
- **Свой центр сертификации.** Плагины проверяют HTTPS по общедоступным корневым сертификатам
  и сертификатам системы. Для сервиса в локальной сети с сертификатом своего ЦС добавьте его в
  системное хранилище или укажите файл: переменная `SSL_CERT_FILE=/data/ca.pem` (в Docker — файл
  в томе `/data`). Нужен перезапуск.
- **Ресурсы** — строка «Получает 64 МиБ памяти, файлы до 16 МиБ за раз, 10 с работы…». Их задают
  три множителя ([подробно](dev/plugins.md#лимиты)): память (×1 — 64 МиБ, четверть из них — данные
  за один вызов), время (×1 — 10 с работы самого плагина и 60 с всего) и порций фоновых задач
  одновременно. Плагин просит их в манифесте — это видно в строке прав («просит: память ×4…») и
  утверждается включением. Вкладка «Системные» окна плагина — выбрать другие; «Как в манифесте» —
  вернуть. Больше `[plugins] max_memory` памяти не получит ни один плагин
  ([настройки](configuration.md#plugins)).
- **Чтения файлов плагином** пишутся в журнал одной строкой на запрос или порцию задач
  («files read by an app», сколько файлов и байт), изменения — по строке на каждое.

Настройки плагинов хранятся в базе (`plugin_configs`), изменения попадают в журнал
(`plugin.install`, `plugin.configure`, `plugin.settings` — только какие ключи изменились, без значений,
`plugin.remove`).

API: [`/api/v1/admin/plugins`](api/admin.md#плагины) · Код: [plugins.rs](../crates/server/src/plugins.rs)

## Хранилище

Вкладка «Сервер», карточка «Хранилище»:

- тип и путь, например «Локальный диск `/data/files`»;
- занято и свободно на диске, сколько занимают файлы RustCloud;
- **от 80% заполнения** — красная полоса и баннер у всех администраторов (проверка раз в 10 минут);
- **скорость записи и чтения** — 64 МиБ несжимаемых данных записываются через хранилище,
  читаются (кэш ОС для файла сбрасывается) и удаляются. Запускается при открытии вкладки,
  если прошлый тест старше часа, или кнопкой.

На виртуальной машине чтение может упираться в кэш хоста и выглядеть завышенным.

API: [`/api/v1/admin/storage`](api/admin.md#хранилище) · Код: [storage.rs](../crates/files/src/storage.rs)

## Журнал

Вкладка «Журнал» — кто, откуда и что сделал, плюс все предупреждения и ошибки сервера.

| Событие               | Когда                                                     |
|-----------------------|-----------------------------------------------------------|
| `server.started`      | запуск сервера                                            |
| `auth.login`          | вход                                                      |
| `auth.login_failed`   | неудачный вход (предупреждение), в т.ч. с паролем приложения (`method=app-password`) |
| `auth.logout`         | выход                                                     |
| `auth.password_change`| пользователь сменил свой пароль                           |
| `account.create`      | создан аккаунт                                            |
| `account.update`      | администратор изменил аккаунт                             |
| `folder.create`       | создана папка                                             |
| `file.upload`         | загружен или заменён файл                                 |
| `file.download`       | скачан файл (докачка и перемотка видео не записываются)   |
| `file.rename`, `file.move`, `file.copy`, `file.delete` | действия с файлами и папками |
| `share.create`, `share.delete` | создана / удалена публичная ссылка               |
| `share.download`      | скачивание по публичной ссылке                            |
| `settings.save`       | сохранён раздел настроек                                  |
| `storage.speed_test`  | тест скорости хранилища                                   |
| `grant.create`, `grant.revoke` | пользователь дал приложению доступ к файлам / доступ закончился |
| `app_password.create`, `app_password.revoke` | создан / отозван [пароль приложения](api/app-passwords.md) |
| `plugin.install`, `plugin.remove` | администратор установил или обновил / удалил плагин |
| `plugin.configure`    | администратор включил, отключил плагин или поменял его лимиты |
| `plugin.settings`     | администратор сохранил настройки плагина (`changed` — ключи, без значений) |
| `app_share.create`, `app_share.revoke` | пользователь поделился [данными приложения](api/app-shares.md) / доступ закрыт (`by`: `owner` или `recipient`) |

- **Поиск** — по пользователю, файлу, адресу и тексту; флажок оставляет только предупреждения и ошибки.
- **Срок хранения** — [`journal.keep_days`](configuration.md#journal), старые записи удаляются автоматически.
- **Нагрузка** — запись идёт пачками в фоне. Если база не успевает, события отбрасываются,
  а страница показывает, сколько потеряно.

API: [`/api/v1/admin/journal`](api/admin.md#журнал) · Как добавить событие: [`audit!`](dev/audit.md)
