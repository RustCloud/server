# RustCloud

Небольшое, быстрое и безопасное self-hosted облако для файлов — альтернатива Nextcloud,
написанная с нуля на Rust.

**Статус: альфа (0.1.0-alpha.1).** Работают аккаунты, файлы, публичные ссылки, предпросмотр
и настройки сервера из веб-интерфейса. Формат данных
может измениться до беты; перед обновлением делайте резервную копию.

- Один исполняемый файл: веб-интерфейс встроен в бинарник. Docker-образ весит около 40 МБ.
- База данных — SQLite (ничего не нужно настраивать) или PostgreSQL. Выбирается строкой подключения.
- Файлы загружаются и скачиваются потоком: размер файла не ограничен памятью сервера.
  Поддерживаются `Range` (докачка, перемотка видео) и `ETag`.
- Встроенные [заметки](docs/apps/notes.md): Markdown-файлы в вашей папке, поиск, автосохранение.
- Встроенный [текстовый редактор](docs/apps/editor.md): любой текстовый файл из любой папки, подсветка синтаксиса.
- Встроенный [календарь](docs/apps/calendar.md) с синхронизацией по CalDAV (iPhone, DAVx⁵, Thunderbird),
  [общими календарями](docs/api/app-shares.md) и [паролями приложений](docs/api/app-passwords.md)
  для телефонов и программ.
- Плагины на WebAssembly в песочнице: свои страницы, данные и доступ только к тем файлам,
  которые разрешил пользователь ([docs/dev/plugins.md](docs/dev/plugins.md)).
- Загрузка файлов и целых папок перетаскиванием; файлы можно перетащить на папку и выбрать
  «переместить» или «копировать». Предпросмотр картинок, видео, аудио и текста.
- Корзина и [версии файлов](docs/api/files.md#версии): заменённый файл можно скачать или вернуть
  в прежнем виде.
- Настройки сервера меняются на странице «Администрирование» и сохраняются в TOML-файл;
  каждое приложение добавляет туда свой раздел. Там же — заполненность и скорость диска
  хранилища и журнал: кто вошёл, что скачал или удалил, неудачные входы, ошибки сервера.
- Безопасность по умолчанию: пароли хешируются Argon2id, сессии можно отозвать в любой момент,
  есть защита от CSRF и подбора паролей. Загруженный HTML или SVG никогда не исполняется
  на домене облака.

Документация: [docs/](docs/README.md) — установка, настройки, API, устройство.

## Быстрый старт

### Docker (SQLite)

```sh
docker build -t rustcloud .
docker run -d -p 8080:8080 -v rustcloud-data:/data --name rustcloud rustcloud
```

### Docker Compose (PostgreSQL)

```sh
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)" > .env
docker compose up -d
```

Compose берёт релизный образ `ghcr.io/rustcloud/server:latest`; настройки — переменными
`RUSTCLOUD_*` в его `environment`. Слушает только `127.0.0.1:8080` и рассчитан на HTTPS reverse proxy
перед ним (подробности — в начале [compose.yml](compose.yml)).

### Без Docker

```sh
(cd web && npm ci && npm run build)   # веб-интерфейс, Node.js 22+
cargo build --release                 # Rust 1.97+
./target/release/rustcloud            # данные — в ./data
```

Откройте `http://localhost:8080` и создайте первый аккаунт: он станет администратором.
Остальных пользователей создаёт администратор на странице «Пользователи», либо можно включить
открытую регистрацию (`accounts.open_registration`).

## Производительность

Замер release-сборки на SQLite (локально, curl, один пользователь):

|                                                |                |
|------------------------------------------------|----------------|
| память в простое / после загрузки файла 500 МБ | 14 МБ / 37 МБ  |
| вход (Argon2id)                                | 16 мс          |
| список папки из 100 файлов                     | 0,8 мс         |
| загрузка / скачивание 500 МБ                   | 0,4 с / 0,13 с |

## Настройки

Все настройки лежат в одном TOML-файле (`--config`, по умолчанию `rustcloud.toml`; в Docker —
`/data/rustcloud.toml`). Файла может не быть: тогда действуют значения по умолчанию, а страница
«Администрирование → Настройки» создаст его при первом сохранении. Все параметры с пояснениями
собраны в [rustcloud.example.toml](rustcloud.example.toml).

- **Ключи верхнего уровня** читаются при запуске: `listen`, `database_url`, `data_dir`, `log`.
- **Таблицы** (`[server]`, `[accounts]`, `[files]`, `[journal]`, позже — таблицы приложений) меняются
  на странице администрирования и применяются сразу, без перезапуска. Сохранение переписывает
  только изменённые значения, комментарии в файле остаются. Если после изменения в UI доступ
  пропал, поправьте файл вручную и перезапустите сервер.
- **Переменные окружения** важнее файла: `RUSTCLOUD_<КЛЮЧ>` для ключей верхнего уровня
  и `RUSTCLOUD_<ТАБЛИЦА>__<КЛЮЧ>` для таблиц (`RUSTCLOUD_SERVER__PUBLIC_URL`). Такие параметры
  в UI показаны, но не редактируются.

| Параметр                      | По умолчанию                          | Что задаёт                                                               |
|-------------------------------|---------------------------------------|--------------------------------------------------------------------------|
| `listen`                      | `0.0.0.0:8080`                        | адрес и порт                                                             |
| `database_url`                | `sqlite://data/rustcloud.db?mode=rwc` | SQLite или `postgres://…`                                                |
| `data_dir`                    | `data`                                | где лежат файлы                                                          |
| `log`                         | `info`                                | уровень логов (`RUST_LOG` важнее)                                        |
| `server.public_url`           | пусто (адрес из браузера)             | адрес для пользователей и публичных ссылок; `https://` → `Secure` cookie |
| `server.other_urls`           | `[]`                                  | другие адреса сервера (например, в LAN)                                  |
| `server.only_listed_urls`     | `false`                               | отвечать только на перечисленные адреса (и `localhost`)                  |
| `server.cors_origins`         | `[]`                                  | сайты, которым можно обращаться к API из браузера                        |
| `server.trusted_proxies`      | `[]`                                  | reverse proxy, чьим `X-Forwarded-For`/`-Proto` можно верить              |
| `accounts.open_registration`  | `false`                               | может ли кто угодно создать аккаунт                                      |
| `accounts.session_days`       | `14`                                  | сколько дней действует вход                                              |
| `accounts.default_quota_mib`  | не задан (без ограничений)            | квота для новых аккаунтов                                                |
| `accounts.max_login_failures` | `10`                                  | неудачных входов на аккаунт за 15 минут (с одного IP — ×5)               |
| `files.max_upload_mib`        | не задан (без ограничений)            | максимальный размер загружаемого файла                                   |
| `files.trash_days`            | `30`                                  | сколько дней удалённое лежит в корзине (`0` — без срока)                 |
| `files.versions_keep`         | `10`                                  | сколько последних версий файла хранить в любом случае                    |
| `files.versions_days`         | `30`                                  | и все версии за столько дней (оба `0` — версий нет)                      |
| `journal.keep_days`           | `90`                                  | сколько дней хранится журнал действий                                    |

За HTTPS-прокси (nginx, Caddy) укажите `public_url = "https://…"` и адрес прокси в `trusted_proxies`.
TLS сам RustCloud не терминирует.

## Как устроено

```text
crates/
  core/           общий тип ошибки, трейт BlobStore, валидация
  plugin-api/     контракт приложений: манифест, версия API, WIT
  wasm-host/      запуск WASM-плагинов в песочнице
  db/             схема (сущности SeaORM и миграции), PostgreSQL или SQLite
  storage-local/  BlobStore: файлы в локальной папке
  auth/           аккаунты, способы входа, сессии, /api/v1/auth и /api/v1/admin
  files/          дерево файлов, загрузка и скачивание, квоты, публичные ссылки
  server/         бинарник rustcloud: конфиг, сборка модулей, встроенный веб
web/              интерфейс на Svelte 5 (встраивается в бинарник при сборке)
apps/notes/       плагин «Заметки» (WASM, встроен в образ)
apps/calendar/    плагин «Календарь» с CalDAV (WASM, встроен в образ)
```

Расширяемость держится на трейтах-стратегиях:

- **`CredentialProvider`** (`auth`) — способ входа. Сейчас есть пароль. LDAP — ещё одна реализация
  этого трейта. OIDC работает через редирект: его обработчик проверяет ID-токен и вызывает
  `Auth::sign_in_external`, который при первом входе находит или создаёт аккаунт. Таблица `identities(provider, subject)` хранит любые способы входа без изменения схемы.
- **`BlobStore`** (`core`) — где лежат байты файлов: локальный диск сейчас, S3 и другие позже.
- **Модули** (`auth`, `files`) приносят свои маршруты (`router()`), а `server` только объединяет их.
  Так же будут подключаться будущие приложения.
- **Права доступа** решаются в одном месте — `Files::check_access`. Группы и расшаривание между
  пользователями добавятся туда.

## API

JSON API под `/api/v1`. Ошибки приходят в виде `{"error": {"code": "FILE_NOT_FOUND", "message": "…"}}`.
Браузер аутентифицируется HttpOnly-cookie и обязан передавать `X-Requested-With` в запросах, которые
меняют данные. API-клиенты используют `Authorization: Bearer <token>` из ответа на `POST /api/v1/auth/login`.

|                                                                     |                                                                               |
|---------------------------------------------------------------------|-------------------------------------------------------------------------------|
| `GET /api/v1/auth/status`                                           | нужна ли первичная настройка, открыта ли регистрация                          |
| `POST /api/v1/auth/register`, `/login`, `/logout`                   | регистрация, вход, выход                                                      |
| `GET`, `PATCH /api/v1/auth/me`; `POST /api/v1/auth/password`        | профиль, смена пароля                                                         |
| `GET`, `POST /api/v1/admin/users`; `PATCH /api/v1/admin/users/{id}` | управление аккаунтами (админ)                                                 |
| `/api/v1/files/…`, `/api/v1/shares`, `/api/v1/public/{token}`       | файлы и ссылки — таблица в [crates/files/src/lib.rs](crates/files/src/lib.rs) |
| `GET /health`                                                       | проверка работоспособности (используется в Docker)                            |

## Разработка

```sh
cargo test --workspace                       # все тесты на SQLite
RUSTCLOUD_TEST_POSTGRES=postgres://postgres@localhost/postgres \
  cargo test --workspace                     # те же тесты на PostgreSQL (каждый тест — своя БД)
cargo clippy --workspace --all-targets -- -D warnings

cd web
npm run dev        # интерфейс на :5173, API проксируется на сервер :8080
npm run check      # svelte-check (типы и Svelte)
npm test           # vitest
```

Браузерный смоук-тест ([web/e2e/smoke.mjs](web/e2e/smoke.mjs)) проходит все основные сценарии в Chromium
против свежего сервера. Команда запуска записана в начале файла.

CI (`.github/workflows/test.yml`): fmt, clippy, тесты на SQLite и PostgreSQL, проверка и сборка веба.
